今天训练一个前沿模型，要读进去的文本量在十万亿到二十万亿 token 这个量级。Llama 3 用了约 15T，DeepSeek-V3 用了 14.8T。这些文本几乎都来自 Common Crawl：一个非营利项目，每隔一两个月把公开网页整体爬一遍并免费放出，每一次这样的抓取叫一个快照，一个快照大致是几十亿个页面、几十 TB 的原始 HTML。目前公开的最大 web 语料 FineWeb 处理了 96 个 Common Crawl 快照、覆盖十一年的网页，扩充后达到 18.5T token。这个数字在过去将近十年里大约每一年半翻一番，而在这十年的大部分时间里，想要更好的模型，答案就是去找更多文本。

这套做法还能用多久是个可以算的问题。网页很大，但不是无限的。而这些字节里真正算数的那一部分，也就是「是文本、是你关心的语言、不是别处内容的副本、也不是机器生成的模板」的那一部分，要比字节总量小得多。

[Villalobos 等人](https://arxiv.org/abs/2211.04325)试着给这件事一个数。所谓 indexed web，指搜索引擎能索引到的那部分公开网页，不含登录墙后的内容、私有数据库和绝大多数动态页面。他们估计 indexed web 上文本的原始存量约 510T token，其中 Common Crawl 覆盖约 130T。但原始存量不等于可以拿去训练的量。假定质量过滤会从去重后的 web 文本里留下 10% 到 40%，再给重复使用留出大约 5 倍的余量，他们得到的**有效**存量是 4×10¹⁴ token 左右。与此同时，训练集规模从 2024 年的约 10¹³ token 出发，每年增长约 0.38 个数量级。

两条指数加一条上限，这就是一道算术题，而它的答案很平淡。

![The token budget](blogs/images/pdata-budget.svg?v=1)

沿这条增长曲线外推，它与上限的交点落在 2028 年，稳稳落在论文自己给出的 2026 到 2032 这个窗口里。这不是在预言 2028 年会发生什么戏剧性的事。它说明的是，「多搞点数据」曾经是一套完整的策略，而这套策略有一个看得见的终点，我们离这个终点已经近到，真正值得问的问题变了。

再看一遍 4×10¹⁴ 是怎么算出来的。它等于原始存量乘以过滤留存率再乘以重复系数。这个乘积里除第一项之外的每一项，都是数据团队能动的。过滤做得更好，留存率就动；重复用得更聪明，系数就动。而把一份固定的语料在各个 domain 和各个训练阶段之间分配得更合理，改变的是每个 token 本身值多少，这一项根本不出现在乘积里，却会出现在模型上。

于是这个领域的重心悄悄从采集移到了萃取：手上已有的一个 token，能榨出多少可用信号。下面每一项技术，都是这个问题的某个版本的答案。过滤、去重和质量分类器决定**哪些** token 值得花算力；配比决定各类数据占多大**比例**；重复决定同一份数据用几**遍**；课程决定这些数据**什么时候**出现。合成数据试图抬高上限本身。而数据污染，是前面任何一步做错了却没被发现时，最后送来的账单。

这篇文章把这六件事都走一遍。凡是我自己算出来而不是引用来的数字，我都会标明，并给出可复现的做法；凡是来自论文的，都给链接并交代条件，因为这个方向上有相当多流传很广的数字，回去查原文会发现是转述错了。

## 一、每一代语料到底新增了什么

开放 web 语料构成了一条相当干净的序列：每一代恰好加进来一个机制。按顺序读一遍，就知道今天的 pipeline 为什么长成这样。

![Published sizes of open pretraining corpora](blogs/images/pdata-corpora.svg?v=1)

C4 出自 2019 年的 T5 工作，大约 750 GB 英文文本。做法是拿一组启发式规则去处理 2019 年 4 月的单个 Common Crawl 快照：删掉不以终止标点结尾的行，删掉命中脏词表的文档，只留语言检测判为英文的部分，去掉重复行。这里每一条规则单独看都站得住，合起来把一堆剥了 HTML 的垃圾变成了可用的语料。之后所有工作都只是在细化 C4 立起的这套模板。

它同时也立起了这个领域最有教育意义的一次失败。两年后有一篇[文档化论文](https://arxiv.org/abs/2104.08758)回过头去问，这些过滤器到底删掉了什么。作者拿方言分类器去看被丢弃的文档，发现非裔美国英语（AAE）的删除率是 42%，西语裔英语是 32%，而白人美国英语（WAE）只有 6.2%，其余英语 7.2%。留下来的语料 97.8% 是 WAE，AAE 占 0.07%。那个 blocklist 是一份被认为不雅的词表。而在某些方言里，表上的一些词本就是日常用语，这样一份词表会怎样对待这些方言，不难想象。没有人是有意的。两年没人发现，因为从「造出语料」到「审计语料」，中间没有任何一步要求有人去量一量输出。一个过滤器是关于你数据的一个假设，而一个没被测量过的假设只是一种偏好。

[CCNet](https://arxiv.org/abs/1911.00359) 引入的是「质量可以**打分**而不只是匹配」。在 Wikipedia 上训一个 KenLM n-gram 模型（KenLM 训练和打分都极快，快到能在语料规模上逐篇跑），用它给每篇 Common Crawl 文档算困惑度，再把语料分成 head、middle、tail 三档。理由是一个在 Wikipedia 上训过的模型觉得不意外的文本，大概率具备像样文字的表层统计特征。这是个 proxy 指标，当时所有人都知道它是 proxy，但它是第三节里所有方法的祖先：它把「坏文本长什么样」这条规则，换成了一个「好文本长什么样」的模型，而模型能泛化，规则不能。

The Pile 走的是完全相反的方向，把 22 个精选子集拼成 825 GiB：PubMed、arXiv、GitHub、书籍、StackExchange、一块 Common Crawl，等等。它赌的是多样性，而这一注在一段时间里押对了。但它真正留下来的贡献，大概是作者当年视为记账工作的那部分。因为每篇文档都带来源标签，The Pile 是唯一一个能让你问出「多用这个、少用那个会怎样」的大型语料。它成了配比研究的标准试验台，它默认的那组 22 个 domain 权重也成了第四节里每种方法都要对比的基线。

[RefinedWeb](https://arxiv.org/abs/2306.01116) 接着提出，那些精选根本没必要：只要把 web 数据的过滤和去重做到位，就足以训出强模型，甚至明显超过当时在 The Pile 上训练出的最好模型。这在 2023 年是个相当逆流的判断，那时候公认的常识是优质文本都在书和论文里。他们的 pipeline 基本就是今天的标准形状，按顺序是：用成人内容黑名单加一套打分系统做 URL 过滤，用 trafilatura 抽正文（一个从 HTML 里剥掉导航栏、广告和页脚、只留文章主体的开源工具），用 fastText 做语种识别（一个基于词向量的轻量线性分类器，快到可以在几百亿篇文档上跑一遍，因而成了大规模 pipeline 里语种识别和质量打分的默认选择），套一遍 Gopher 启发式规则和他们自己的逐行修正（第三节展开），最后做 MinHash 模糊去重和精确子串去重（第二节展开）。他们从 Common Crawl 里拿到 5T token，公开了其中 600B。Falcon 就训在它上面，从此 web-only 这条路线一直占主导。

再往后是透明化的一代，从这一代起，人们开始把 ablation 也发出来，而不只是发数据集。RedPajama 复刻 Llama 1 的配方做到 1.21T token。SlimPajama 在 RedPajama 上跑全局 MinHashLSH，13-gram、Jaccard 阈值 0.8，删掉 49.6% 的字节，剩 627B。一个由称职团队从已经过滤过的来源拼出来的语料，一半是重复。[Dolma](https://arxiv.org/abs/2402.00159) 公开了 3T token，从大约 200 TB 原始文本清洗到 11 TB，工具链和 ablation 一并放出。[FineWeb](https://arxiv.org/abs/2406.17557) 处理了 2013 年夏天到 2024 年 4 月的 96 个 Common Crawl 快照，得到 15T token，后来扩到 18.5T 以上，每一个 ablation 模型都公开了。[DCLM](https://arxiv.org/abs/2406.11794) 把 240T token 的 Common Crawl 标准化成一个 benchmark，配 53 个下游评测和 412M 到 7B 的受控模型规模，让数据精选变成了一件可以比赛的事。

这张图要分两族来读。240T 和 18.5T 那两个池子，是「可以拿到的」。而人们真正训练用的语料要小上一到两个数量级。接下来三节讲的全部内容，都活在这道落差里。

## 二、去重，以及 MinHash 为什么长成一条 S 曲线

web 文本里的重复不是个可以忽略的零头。多数人凭直觉给出的估计都太乐观。

[Lee 等人](https://arxiv.org/abs/2107.06499)在几个标准语料上跑了近似重复检测。C4 里有 3.04% 的训练样本在训练集别处还有一份近似重复，RealNews 上这个数是 13.63%。极端个例比平均值更离奇。他们报告从 C4 里删掉了「一句 61 个词的英文句子，重复了六万多遍」。一句话，六万份，而这个语料已经过了行级去重。

由此产生的后果有两个，而且彼此独立，这也是为什么就算你只在乎其中一个，去重也值得做。第一是评测：训练集与测试集的重叠「影响了标准数据集验证集的 4% 以上」，于是重复会悄悄抬高你用来做决策的那些数字。第二是记忆：去重「让模型逐字吐出记住的文本的频率降到十分之一」。一个把某段文字看了六万遍的模型，等于被明确要求去背它，而它照办了。

容易的情况确实容易。精确去重就是一张哈希表。精确**子串**去重是在拼接后的整个语料上建后缀数组，它能找出所有超过某个长度的重复片段，不管文档边界落在哪，因而能抓到「两篇文档共享一大段模板、其余部分不同」这种非常常见的情形。但这两种都碰不到真正占主导的那类：两篇文档只差一个页头、一个时间戳、一个导航栏，或者一句被改写过的话。

要处理这一类就需要在语料规模上做近似匹配，而这意味着你不能两两比较：文档有 10¹⁰ 篇，两两就是 10²⁰ 次比较。标准答案是 MinHash 配 locality-sensitive hashing。它最核心的那个参数，几乎没有人真正有意识地调过。

把文档里每 k 个连续词切成一个片段，这种片段叫 shingle；一篇文档就是这些片段的集合，于是变成一个巨大全集的子集。你想要的相似度是 Jaccard：交集大小除以并集大小。现在取 shingle 全集的一个随机置换 π，对每篇文档记录 π 在它的 shingle 上取到的最小值。关键事实是，对两篇文档 A 和 B，

$$
\Pr\big[\min \pi(A) = \min \pi(B)\big] \;=\; \frac{|A \cap B|}{|A \cup B|} \;=\; J(A, B)
$$

论证只要一行。A ∪ B 里 π 值最小的那个元素，等概率地是并集中的任何一个，因为 π 是均匀随机置换。而两个最小值相等，当且仅当这个元素恰好落在交集里。于是概率就是 |A ∩ B| / |A ∪ B|，也就是 Jaccard 的定义。

这就给了你一个估计量：m 个独立置换构成的签名相当于 m 次 Bernoulli(J) 抽样，于是两个签名在同一位置上取值相等的比例，把 Jaccard 估到 1/√m 的精度。你把集合比较换成了整数比较，而签名相对文档本身小得可以忽略。

LSH 则把这个估计量变成一个检索结构，让你根本不去看绝大多数文档对。把 m 行签名切成 `b` 段、每段 `r` 行，m = b·r，每段各自哈希进一张表。两篇文档只要在至少一段里撞上，就成为**候选**。在某一段里撞上，要求这 `r` 行全部相同，在真实相似度 `s` 下概率是 `s^r`，而各段之间独立，于是

$$
P(\text{candidate}) \;=\; 1 - (1 - s^{r})^{b}
$$

这是关于 `s` 的一条 sigmoid，拐点落在 `(1/b)^{1/r}` 附近。这个表达式才是真正控制去重激进程度的旋钮。它不是你在代码里某处设定的相似度阈值，而是你决定怎么切分哈希预算之后**被动得到**的阈值，而它极容易从你抄来的那份配置里一并继承过来。

![The LSH S-curve, measured and predicted](blogs/images/pdata-lsh.svg?v=1)

曲线是公式，点是量出来的。我构造了重叠度可控的文档对，在 5-gram shingle 上用 180 个置换算真实的 MinHash 签名（置换用模 Mersenne 素数的仿射映射实现），切成 20 段每段 9 行建索引，再记录每一对实际有多大比例被捞成候选。理论和实测在采样噪声以内吻合，这是个平淡的结果，也是正确的结果。

右边那栏把同样 180 个哈希的预算拆成五种不同的因数分解。这五行之间，语料、shingle 大小、计算量都没有任何变化。但 45 段 × 4 行会一路捞到 Jaccard 0.39，把只共享三分之一内容的文档也当成重复；而 5 段 × 36 行连 0.96 以下的都不看一眼，会漏掉几乎所有真实的近似重复。所有合理的配置都落在这两个极端之间，而它们之间的差别只是一个整数分解。如果你见过两个团队都号称在做「阈值 0.8 的 MinHash 去重」，删除率却差得很远，原因通常就在这里。

还有两个选择的分量差不多。一个是粒度：文档级、段落级和行级去重删掉的内容差别很大，SlimPajama 的 ablation 表明跨来源的全局去重和来源内部的局部去重不可互换，因为跨来源的重复恰恰是那些在多个精选集合里都出现的文档，而这类文档恰恰看起来最重要。另一个是语义：[SemDeDup](https://arxiv.org/abs/2303.09540) 用预训练模型给文档做 embedding，对 embedding 聚类，在簇内删掉近邻，能抓到一个 shingle 都不共享的重复对，因为其中一篇是另一篇的改写或翻译。在 LAION 的一个子集上，它「删掉 50% 的数据而性能几乎不掉，训练时间直接减半」。它自己在 C4 上的结果要克制得多，效果超过此前的去重方法，效率提升约 15%，作者把差距归因于 C4 本来就已经被部分精选过。这两个数字要放在一起记：语义去重在未清洗的多模态数据上空间极大，在别人已经清过一遍的文本上要小得多。

## 三、质量过滤：从规则到分类器

去重删掉的是冗余的文本。质量过滤删掉的是本来就不值得要的文本，而后者难定义得多，相应地也更容易做错。

Gopher 的 pipeline 立起了基于规则的标准，今天每一条 pipeline 都在重新实现它的某个版本：按词数、平均词长、符号与词的比例、以项目符号开头或以省略号结尾的行占比这类文档统计量来过滤；删掉文档内部的重复文本；做文档之间的去重；再删掉与测试集重叠的文档。具体阈值在各家复现之间有出入，追着调它们基本是浪费时间。更要紧的是这些过滤器叠在一起会发生什么，而 Dolma 把这件事直接量了。

![What survives a composed pipeline](blogs/images/pdata-funnel.svg?v=1)

这里每一级的比率都是论文里的，连乘是我做的。Gopher 的整套规则标记了 15.23% 的 UTF-8 字符待删。C4 的无标点规则标记了 22.73%。模糊加精确去重删掉大约一半。一个只保留最高十分之一的模型分类器又删掉九成。乘起来，抽出来的文本大约剩 3%。

这个数字改变了 pipeline 的性质。没有人在设计一个系统时打算丢掉 97% 的输入。每一级都是单独设计、单独评估的，每一级单看都很保守，而复合结果非常凶狠。这也意味着链条最后那一级，也就是分类器，在绝对量上干了最多的活，受到的审视却最少，因为轮到它的时候，前面几级已经把语料弄得看上去很干净了。

C4 的 NoPunc 规则**单独使用**时，在困惑度和下游任务上都优于 C4 的整套规则，也优于 Gopher 的整套规则；总体最好的配置是 Gopher 全套加上 C4 NoPunc。规则更多不等于质量更好。这一套规则里最粗暴的那一条，也就是「扔掉不以标点结尾的行」，贡献了大部分收益，大概是因为它是一个极其有效的导航栏、标签云和商品列表检测器，而网页的大部分正是这些内容。

2024 年的共识从规则转向了学出来的分类器，而两个参考实现在「向什么学」这件事上做了很能说明问题的不同选择。

DCLM 训了一个 fastText 分类器，正类是指令格式的文本，具体来说是 OpenHermes 2.5 和 r/ExplainLikeImFive（ELI5），负类是随机网页。隐含的理论是：像一段好解释的文本，就是值得训练的文本。FineWeb-Edu 走的是更贵的一条路：让 Llama-3-70B-Instruct 给 46 万个页面的教育价值打分，把这些判断蒸馏进一个小分类器，在阈值 3 处达到 F1 82%，再拿它去给全部 15T token 打分，花掉 6000 个 H100 小时。隐含的理论是：一个强模型已经知道什么是好文本，你要做的只是把它的意见变得足够便宜、能在这个规模上用。

两条路都成立，而且都很成功。FineWeb-Edu 报告一个 1.71B 模型在 350B token 上训练后，MMLU 从 33% 升到 37%，ARC 从 46% 升到 57%。DCLM 的结论更强，也把一般原则直说了，"model-based filtering is key"：DCLM-Baseline 让 7B 模型在 2.6T token 上拿到 64% 的 5-shot MMLU，比此前用开源数据训出的最好模型高 6.6 个百分点而算力少 40%，达到这个水平所用的算力只有 Llama 3 8B 的六分之一。

这里到底取得了什么，值得说准确，因为「model-based filtering 有效」经常被读成「我们现在知道怎么度量数据质量了」，而后者并没有发生。两组人都没有定义质量。两组人都是挑了一个自己相信与质量相关的 proxy 语料，而做出来的过滤器会继承这个选择的全部性质。「读起来像 ELI5 回答的文本」和「一个 70B 模型判为有教育价值的文本」是两个不同的目标。对一个之后还要 post-train 成编程 agent 的模型来说，这两个目标显然都不一定是对的那个，而且没有人证明过不同过滤器之间的排序在不同下游用途上是稳定的。

[A Pretrainer's Guide](https://arxiv.org/abs/2305.13169) 为了系统研究这类取舍，预训练了 28 个 1.5B 模型，把其中一个实例讲明了：把毒性从预训练里滤掉，会削弱模型之后**识别**毒性的能力。在这个维度上，质量和能力指向相反的方向。没有什么特别的理由认为这是唯一一个如此的维度，而认真去找过其他维度的人很少。

## 四、配比，当成一个优化问题

语料一旦有了 domain，就有了比例，而比例是数据工作里唯一一块看上去是良定义优化问题的地方：一个低维连续参数，一个勉强可微的目标，一套明确的评估。技术上最有意思的工作跑到了这里，并不意外。

这个问题比看上去难，原因值得先说清楚：你不训一个模型就没法评估一个混合，一次前沿训练要花掉几百万美元，而混合有不可数多种。下面每一种方法，本质上都是在想办法把这个评估做得便宜到可以搜索。

DoReMi 把它当成一个 minimax 问题来解。用 [group distributionally robust optimization](https://arxiv.org/abs/2305.10429) 训一个小 proxy 模型：模型这一侧最小化相对固定参考模型的最坏情况超额损失，domain 权重由内层最大化那一侧给出。然后把这组权重拿去训一个大 30 倍的模型。从 280M 的 proxy 到 8B 的目标，这套做法"把平均 few-shot 下游准确率提升了 6.5 个百分点，并且只用 1/2.6 的训练步数就达到了基线准确率"（基线是 The Pile 的默认 domain 权重），绝对量上是 75k 步对 200k 步。proxy 的开销约占目标训练 FLOPs 的 8%。

全部 22 个 Pile domain的困惑度都改善了，**包括那些被这个方法降权的 domain**。而这个重新加权一点都不温和。Pile-CC 从 0.1121 升到 0.6057。ArXiv 从 0.1052 掉到 0.0036。PubMed Central 从 0.1071 掉到 0.0046。

这个方法把 arXiv 砍到原权重的三十分之一，而 arXiv 的困惑度**变好了**。比较自然的解读是：一个专门 domain 最需要的不是更多的它自己，而是一个已经把语言学明白的模型，而通往那里最便宜的路是 web 文本。如果你把预训练想成教科目，这件事非常反直觉；如果你把它想成学一个分布、而各个科目只是这个分布的条件切片，它就一点都不奇怪。

[DoGE](https://arxiv.org/abs/2310.15393) 把鲁棒性目标换成一个一阶目标，顺带把配比和 influence function 接上了。给每个 domain 打分，分数是它的梯度与全部 domain 梯度之和的内积：哪个 domain 的梯度方向更接近总方向，它的数据就对所有 domain 都有帮助，于是拿到更高的权重；权重按 mirror descent 更新。这个分数可以拆成跨 domain 的对齐项，加上该 domain 自己的梯度范数，所以「难」和「有用」在里面是纠缠的，这是一个实打实的局限而不是技术细节。用 82M 的 proxy 模型去指导 684M 的目标模型，5-shot 推理上比均匀混合高 1.7 个百分点。

[RegMix](https://arxiv.org/abs/2407.01492) 干脆不去建模机制，结果反而走得更远。训 512 个 1M 参数的模型、每个 1B token，混合比例从一个刻意偏向极端的 Dirichlet 分布里采样。Dirichlet 是直接在「一组非负、和为 1 的比例」上采样的分布，而这些比例的全体构成一个单纯形；把浓度参数调小，采出的混合就会偏向单纯形的角落，也就是某一个 domain 占绝大部分，而不是全挤在均匀混合附近。这样回归的训练样本才覆盖得开。拟合一个从混合比到验证损失的回归器，再优化这个回归器。整套流程约占单次 1B 训练 FLOPs 的 2%。

有两个细节比主结论更有信息量。第一，LightGBM 大幅胜过线性回归，预测 1B 模型排序时 Spearman 97.1 对 88.0，这说明单纯形上的损失曲面有明显的非线性，也说明凡是拿线性模型去拟合混合效应的人，都在白白损失精度。第二，预测出的最优混合，在 64 个各训 25B token 的 1B 候选模型里排第一，也就是说小规模上的排序迁移过去了。论文把这件事表述为 "data mixture effects transcend scaling laws"，意思是在极小规模上找到的混合**排序**能延续到大规模，尽管绝对损失值不能。正是这条性质让 proxy 模型搜索成为可能，而这条性质是经验观察，不是推导出来的。

RegMix 还从一条完全不同的路线独立复现了 DoReMi 最反直觉的那个发现：web 语料，而不是那些人人称之为高质量的来源，与下游性能的相关性最强。两项在方法论上毫无共同点的工作得出了同一个结论：Common Crawl 的比例应该定得比人凭直觉会选的高得多。

[Data Mixing Laws](https://arxiv.org/abs/2403.16952) 给这个曲面本身配了一个函数形式，于是你可以外推而不只是内插。记 `r_j` 为训练 domain `j` 的比例，`L_i` 为验证 domain `i` 上的损失，

$$
L_i(r_1, \ldots, r_M) \;=\; c_i + k_i \exp\Big(\sum_{j=1}^{M} t_{ij}\, r_j\Big)
$$

其中 `c_i` 是任何混合都消不掉的那部分损失，`k_i > 0` 是尺度，`t_ij` 刻画训练 domain `j` 与验证 domain `i` 之间的交互，`t_ij` 为负表示 `j` 对 `i` 有帮助。作者比较了四个候选形式，选了这个，因为它拟合得和最灵活的那个一样好而系数更少。真正让它可用的是一个结构性选择：指数落在求和号**外面**，一次线性组合的指数，参数量因此随 domain 数线性增长，而不是平方增长。总目标是 `Σ_i s_i L_i`，`s_i` 是验证集里各 domain 的比例。

外推的机制他们叫 nested scaling laws。在小模型、少步数上拟合 mixing law；再各自拟合损失对训练步数、损失对模型规模两条律；把三者套起来，去预测一个大模型长时间训练在一个没见过的混合上会是什么表现。收益是给 1B 模型在 100B RedPajama token 上找到的混合，"达到了默认混合多训 48% 步数才能达到的性能"，换个说法就是用 73% 的步数达到默认混合的最终水平。

既然形式是显式的，直接求值就行。下面是一个三 domain 的实例，交互项的正负号取得合理，在整个单纯形上求值，其中一个 domain 在验证混合里权重更高。

![The loss surface over a three-domain simplex](blogs/images/pdata-mixing.svg?v=1)

这张图有两个特征是普遍的。一是最优点在内部，而且不是均匀混合，自动配比之所以还是个问题、而不是一个有显然答案的已解决问题，理由全在这里。二是这个曲面在最优点附近很平、靠近边界很陡：这里均匀混合与最优之间差 0.0129 nat（nat 是以自然对数为底的信息量单位，也是交叉熵损失的默认单位，1 nat ≈ 1.44 bit），按 C4 的 scaling law 折算，相当于在 100B token 的预算下多给 21% 的 token，而走到单纯形的角上，代价是这个的好几倍。

落到实践上有两句话。配比值得做，因为当 token 是约束时，一个 token 预算的 21% 是很大一笔。配比不值得在第一位有效数字之后继续纠缠，因为最优点附近这个曲面足够平，好混合与最好混合之间的差别小于多数评测的噪声。

[CLIMB](https://arxiv.org/abs/2504.13161) 处理的是上面所有方法共同的前提：你手上到底有没有 domain 标签。The Pile 有，因为它就是从带标签的来源拼出来的。Common Crawl 没有。CLIMB 把文档做 embedding，在 embedding 空间里聚类，把 proxy 加 predictor 的搜索跑在簇权重而不是来源权重上，迭代地向更好的混合逼近。用找到的混合继续训练一个 1B 模型 400B token，比 Llama-3.2-1B 高 2.0 个百分点；他们还放出了 ClimbLab，一个组织成 20 个簇的 1.2T token 语料，作为研究底座。

这一步在概念上的意义值得点明：簇不是 domain。配比这套形式化里，没有任何一处要求这个划分对人类有意义；而一旦不再要求这一点，「怎么划分」本身就成了另一个可以优化的对象。

## 五、重复：同一个 token 能用几次

到目前为止的一切都默认每个 token 只看一遍。池子一旦固定，这件事就不再是默认而是一个选择，而它恰好是所有选择里理论最干净的一个。

[Muennighoff 等人](https://arxiv.org/abs/2305.16264)跑了四百多次训练，参数从 10M 到 9B，token 最多 900B，epoch 最多 1500，专门去刻画重复数据值多少。他们的答案是一个两参数模型，好写也好用。

记 `U_D` 为手上 unique token 的数量，`R_D = D/U_D − 1` 为重复次数，于是 `R_D = 0` 表示只跑一个 epoch。把**有效数据** `D'` 定义为能产生同样损失所需要的新鲜数据量，那么

$$
D' \;=\; U_D + U_D\, R_D^{*}\left(1 - e^{-R_D / R_D^{*}}\right)
$$

在超额参数 `R_N` 下，有效参数 `N'` 有一个对称的表达式。在他们的实验上拟合得到 `R_D* = 15.39`、`R_N* = 5.31`，作者把这两个量分别描述为重复数据和超额参数的半衰期。

有意思的是这个函数形式本身。当 `R_D → 0`，指数展开成 `R_D`，于是 `D' ≈ U_D(1 + R_D) = D`：最初几次重复是按面值算的，重复是免费的。当 `R_D → ∞`，指数项消失，`D' → U_D(1 + R_D*)`：存在一个硬上限，任何重复都不可能把一份语料推过它自身的 `1 + R_D* = 16.4` 倍。关于重复的一切，都取决于你坐在这条曲线的哪一段。

![What repeated epochs are worth](blogs/images/pdata-repetition.svg?v=1)

四个 epoch 换来相当于 3.73 份 unique 语料的价值，是四个 epoch 全用新数据时的 93%。论文那句被引用得最多的话，"重复至多约 4 个 epoch，损失相比全新数据几乎没有变化"，说的就是这件事。十六个 epoch 换来 10.58 份，是 66%；你现在有三分之一的算力花在了没有回报的地方，但如果新鲜 token 本来就拿不到，这仍然可能是对的选择。到第 44 个 epoch，可拿的 16.4 份里你已经收了 15.45 份，而边际的那个 epoch 只值 0.063 份，大约是第一个 epoch 的十六分之一。

这些数字要配两条限定。论文观察到训了 44 个 epoch 的模型实际上会发散，所以这条曲线的远端描述的是一个即便算术上划算、你也不会真去跑的区间。另外，流传很广的那句「到 40 个 epoch 左右收益归零」在论文里根本不存在。论文说的是有意义的收益延伸到大约 16 个 epoch，"越过之后收益衰减得极快"。40 是一个传播很广的二手转述；上面那个公式才是原始对象，而它既更精确也更有用。

## 六、数据固定时，算力该怎么分

把重复曲线放回算力预算里，它就不再是个趣闻而变成一个决策，因为它改变了 scaling 里最基本那个问题的答案。

[Chinchilla](https://arxiv.org/abs/2203.15556) 把损失曲面拟合成 `L(N, D) = E + A/N^α + B/D^β`，`E = 1.69`、`A = 406.4`、`B = 410.7`、`α = 0.34`、`β = 0.28`，结论是在固定算力预算下参数和 token 应该等比例增长，折算下来大约每个参数配 20 个 token。这条建议假设 unique 数据要多少有多少。而在 unique token 预算固定的前提下它就不再适用了，因为在质量不变的条件下，「更多 token」已经不是你能买到的量。

Muennighoff 等人的处理办法是把有效量代进一个在 C4 上重新拟合的 Chinchilla 形式：

$$
L(N', D') \;=\; 1.87 + \frac{521}{N'^{\,0.353}} + \frac{1488}{D'^{\,0.353}}
$$

现在这个优化有了真实的结构。把算力花在参数上，一旦模型远大于数据所能支撑的规模，就会吃到 `R_N` 那一侧的惩罚；花在多过几遍数据上，一旦重复次数上去，就会吃到 `R_D` 那一侧的惩罚。那就把 `U_D` 固定在 1T unique token，扫算力预算 `C = 6ND`，对每个预算在模型规模上搜索，epoch 数由 `D / U_D` 直接给出。

![Optimal epochs against compute at a fixed unique-token budget](blogs/images/pdata-allocation.svg?v=1)

在 10²³·⁵ FLOPs 以下，最优解一次都不重复。每多一份算力都进了参数，epoch 数牢牢钉在 1，这正是 Chinchilla 的区间：数据不是绑定约束，所以就当它是无限的。越过这个门槛之后，模型规模已经远超 1T token 所能支撑的规模，`R_N` 的惩罚超过了 `R_D` 的惩罚，于是最优解改买 epoch。到 10²⁵ FLOPs，它要的是一个 229B 参数的模型，在数据上过 7.3 遍。

这个门槛随你手上的数据移动，规律很干净：100B unique token 在 10²¹·⁵ FLOPs 开始重复，1T 在 10²³·⁵，10T 在 10²⁵·⁵，数据每多一个数量级，就能在重复变成正确选择之前多消化两个数量级的算力。

外推到公开人类文本的全部有效存量，也就是 4×10¹⁴ token，重复大约在 10²⁷ FLOPs 开始划算。而 Villalobos 等人估计，模型耗尽这份存量对应的算力是 5×10²⁸ FLOPs。这两个数字相差约两个数量级，这才是「数据墙」这个词的实际内容。它不是一道训练突然失效的断崖，而是越过之后，额外的算力买到的是 epoch 和参数而不是新的信息，算力的回报因此改变了性质。

## 七、课程：不是所有 token 都该在同一时刻到场

第四节那样提出的配比，要的是整个训练过程共用一组比例。有两个各自独立的工业结果说明，这样做会白白丢掉相当一部分收益，两者从不同方向走到了基本同一个技术上。

Llama 3 在最后 40M token 上把学习率线性退火到零，同时上采样极高质量的来源，并对退火阶段的 checkpoint 做平均。报告的效果很大：退火让一个 8B 模型"在 GSM8K 和 MATH 验证集上分别提升了 24.0% 和 6.4%"。这个数字要配两条限定。这个 ablation 退火用的是这两个 benchmark 的**训练集**，所以它量的是一次定向退火能把一个定向 benchmark 推多远，而不是通用能力。以及在 405B 模型上提升可以忽略，这提示机制是小模型需要这个示范，而大模型已经自己泛化出来了。

同一篇论文还把退火变成了一种测量手段。要评估一个候选数据集，取一个训到 50% 的 checkpoint，在 40B token 上把学习率退火到零，其中候选数据集占 30% 权重、默认混合占 70%，然后读取 benchmark 分数的变化。这样每个候选只花一次短训练，而在更老的方法论下每个候选要跑一整套 scaling law。它把数据评估从一个研究项目变成了一件每有人提议一个数据集就能跑一遍的事。

[OLMo 2](https://arxiv.org/abs/2501.00656) 把同样的直觉固化成一个有名字的训练阶段，而且报告得比任何人都细。Stage 1 大约 3.9T token，其中超过 95% 是 web 数据。Stage 2 他们叫 midtraining，从一个约 843B token 的高质量池子里取样，这个池子由过滤后的 web、学术文本、问答数据、指令数据和合成数学题拼成，采样到 50B、100B 或 300B token，其中 DCLM 过滤过的 web 仍然供应约一半预算，好让模型不被整个拽离原来的分布。7B 上他们跑三次只有数据顺序不同的 50B 退火，再把权重平均。

![Midtraining, before and after](blogs/images/pdata-midtrain.svg?v=1)

这些是论文里的数字，不是我量的。GSM8K 在 7B 上从 24.1 到 67.5，13B 上从 37.3 到 75.1。DROP 从 40.7 到 60.8。十项 benchmark 的平均在 7B 上移动 10.6 分，13B 上 10.3 分。

Stage 2 视采样规模不同，只占 token 预算的 1% 到 8%，却把平均分推了十分，超过绝大多数架构改动这些年做到过的。midtraining 里发生的事情，无论是什么，都不是「多训了一点」。更像是模型终于知道了这些 token 是拿来干什么的。

他们也给逐个数据集的评估协议起了名字，microannealing，就是把 Llama 3 那套测量方法在每个候选数据集上各跑一遍。两个实验室各自独立地既收敛到同一个技术、又收敛到把它当测量工具用，在这个领域里已经是相当强的信号了。

于是第四节那种单一的全局混合，本身就是个错误的优化对象。这些结果描述的是一张**时间表**，一个随训练过程变化的混合，而第四节里所有方法都不在时间表上优化，它们优化的是一个点。Data Mixing Laws 走得最近，因为它能预测在持续训练中避免灾难性遗忘的混合，但「在单纯形上优化一条轨迹」这个一般问题基本还是开放的。

## 八、合成数据，以及它失效时的形状

如果人类文本的存量是固定的，那么最直接的一步就是自己造。这里的证据确实是两面的，而这两面通常被拿来互相反驳，实际上它们描述的是不同的情形。

有效的那一面是 [phi-1](https://arxiv.org/abs/2306.11644)：1.3B 模型，训练数据是 6B token 的过滤后代码，加上约 1B token 由 GPT-3.5 生成的教科书与习题，8 张 A100 训 4 天，HumanEval pass@1 达到 50.6%，MBPP 55.5%；350M 的版本也还有 45%。它的成分经常被说错，所以值得说准确：那 6B 是从 The Stack 和 StackOverflow 里过滤出来的**代码**，不是通用 web 文本，而合成部分大约占七分之一的 token。这里主张的并不是合成数据可以替代真实数据，而是少量目标明确的合成数据叠在被狠狠过滤过的真实数据上，胜过大得多的一堆未过滤数据。

[WRAP](https://arxiv.org/abs/2401.16380) 提出的主张对数据受限的世界最要紧。它不生成新内容，而是用一个指令微调过的模型把已有的 web 文档改写成不同风格，报告在 C4 上预训练加速约 3 倍，算力相同的条件下 Pile 各子集的困惑度改善超过 50%，13 个任务的 zero-shot 平均提升超过 2%。改写是在用算力换一种数据，它的行为接近 unique 数据，而 unique 数据恰恰是第五节认定为稀缺的那种资源。既然重复的上限是语料的 16.4 倍，而改写产出的数据既不完全新鲜、也不完全算重复，那么真正有意思的问题是改写数据落在那条曲线的哪个位置，而这件事没有人量过。

失效的那一面是 Nature 上关于 [model collapse](https://www.nature.com/articles/s41586-024-07566-y) 的结果："不加区分地把模型生成的内容用于训练，会在所得模型里造成不可逆的缺陷，原始内容分布的尾部会消失。"这个结果经常被当成某种神秘的涌现病理来引用。它不是。机制非常初等，复现它只要十行代码。

用极大似然在 `n` 个样本上拟合一个高斯。从拟合出的分布里抽 `n` 个新样本。再拟合。如此往复。每一步的均值估计都是无偏的，每一步也都做对了。但极大似然的方差估计恰好偏小：它除的是 `n` 而不是 `n−1`，算出来的方差只有真实方差的 `(n−1)/n`。于是跨代有

$$
\mathbb{E}[\sigma_g^2] \;=\; \left(\frac{n-1}{n}\right)^{g}\sigma_0^2
$$

更强的说法是，`σ_g²` 是一个非负鞅，因而几乎必然收敛。而它唯一能收敛到的值是零。分布收缩成一个点，而且不管每一代单独执行得多仔细，都会这样。

![Variance under recursive refitting](blogs/images/pdata-collapse.svg?v=1)

取 `n = 100`、300 条独立链，量出来的平均方差与那条几何预测严丝合缝，本该如此，因为那个预测不是近似。实践上重要的是那条绿线：第 `g` 代模型分配到**原始**分布 ±2σ 之外的概率质量，从第 0 代的 4.6% 掉到第 100 代的 0.08%，到第 200 代在数值上已经是零。先消失的是尾部，而稀有知识就住在尾部。

所以合成数据这场争论的两面并不真的冲突。坍缩说的是一个**闭环**，每一代唯一的输入是上一代的输出。phi-1 和 WRAP 说的是锚定在真实数据上的单代合成。区分它们的条件是新鲜的真实数据有没有持续进入这个循环，而与多数关于合成数据的分歧不同，这个条件是可检验的，不是哲学问题。不太舒服的地方在于，随着网页里模型生成的内容越来越多，这个环会自己合上，不需要谁去决定合上它，而目前没有人有可靠的办法去测量这个过程走到了哪一步。

## 九、污染，以及 n-gram 去污染为什么不管用

这篇文章里的每一个论断都是一个 benchmark 数字。最后一个问题是这些数字究竟还算不算数，而诚实的答案比我们希望的要弱。

工业界的标准防线是 n-gram 去污染：凡是与测试题共享某个 n-gram 的训练文档就从训练集里删掉，`n` 通常取 8 到 13。它便宜，容易验证，也确实能抓住那些原封不动被爬进语料的 benchmark 副本。每一家大实验室都做了某个版本的它。

[Yang 等人](https://arxiv.org/abs/2311.04850)证明这道防线轻易就能绕过，而最扎眼的地方是绕过它根本不需要有人蓄意为之。把一道测试题改写一遍，或者翻成另一种语言再翻回来，n-gram 重叠就归零了，而这道题真正考的能力一点没变。他们的主结论是"一个 13B 模型可以轻松过拟合一个测试 benchmark，达到与 GPT-4 相当的高分"。在改写过的 MMLU 上，Llama-2 7B 从 45.3 升到 88.5，13B 从 54.8 升到 89.9，而标准的 n-gram 去污染什么都没检测到。

这个机制与其争论不如直接看，下面是在一对样本上量出来的结果。

![n-gram overlap between a benchmark item and its paraphrase](blogs/images/pdata-contamination.svg?v=1)

这是一道算术应用题和它的一个改写版之间量出来的重叠，任何像样的模型对这两道题都会给出同样的答案。unigram 重叠是 38%，bigram 15%，trigram 3%，从 4-gram 开始就是精确的零。一个 n = 13 的去污染过滤器不只是漏掉了这一对，它根本看不见这一对；n = 8、n = 5 时同样如此。而**能**抓住改写的那个 n，大约是 2 或 3，会把语料删掉大半，因为常见的三元组到处都是。这个参数没有一个取值是管用的。

这不是假想出来的污染。同一份工作量出 HumanEval 有 8.5% 与 RedPajama-Data-1T 重叠、15.9% 与 StarCoder-Data 重叠、18.9% 与 The Stack 重叠。这些还只是 n-gram 匹配**看得见**的那部分。而这几个语料被很多开源模型训练用过，HumanEval 又几乎每篇代码模型发布都会引用。

检测这一侧的文献对自己走到哪儿很坦白。[Min-K% Prob](https://arxiv.org/abs/2310.16789) 要回答的是某段文本是否在某个模型的预训练数据里，而且不能访问语料、也不能用参考模型，这正是你评估别人的模型时的真实处境。它取文本中概率最低的 k% 个 token，对它们的对数似然求平均，依据是模型没见过的文本里会有它赋予极低概率的离群 token，而背下来的文本里不会有。WIKIMIA 用 Wikipedia 的编辑时间戳，构造出哪些文本一定在训练数据里、哪些一定不在的金标准；在这个 benchmark 上，Min-K% Prob 达到 0.72 的平均 AUC，此前最好的方法是 0.67，论文把这个改进写成 7.4%，这是相对值，不是 7.4 个 AUC 点。

0.72 的 AUC 是一个真实的信号，也是一个不合格的检验。它足以支撑一个关于大批文档的统计性判断，远不足以裁定某个具体 benchmark 是否在某个具体语料里。所以我们实际所处的位置是这样：对一份不是自己构建的语料，我们无法验证某个评测是否干净；多数已发表的模型比较里至少有一方的数据是不公开的；于是污染状况在两边都是未知，而不是已知没问题。

## 十、这些算术合起来说明什么

把这些数字放到一处，会显出一个任何单独结果都看不出的形状。

公开人类文本的有效存量在 4×10¹⁴ token 附近，而数据集规模在 2028 年前后追上它。叠起来的过滤只留下抽取文本的百分之几，其中删得最多的是分类器那一级，而它由一个基本任意的正例选择所定义。去重的激进程度取决于一个整数分解，多数团队是继承而不是选择了它。配比大约值一个 token 预算的 20%，再多没有了，但最优点附近的曲面足够平，一个像样的混合就能拿到其中大部分。重复至多值你 unique 语料的 16.4 倍，而对 1T 的池子它在 10²³·⁵ FLOPs 变成正确的分配，对整个 web 则是 10²⁷。十分之一的预算放在最后花，值 10 分的 benchmark 平均分。合成有效的前提恰好是真实数据持续进入循环，而一旦不再进入，它失效的方式是可以证明的，不只是经验上的。而上面这些测量，目前都没法拿一个谁都确信干净的 benchmark 去验证。

这份清单里最大的五个杠杆，有四个是分类器的正例、去重粒度、混合比例和 midtraining 时间表，都是某个人在很早的时候定了一次的选择，往往是从上一个项目抄过来的，之后很少回头看。而吸引了几乎全部注意力的那一个，语料规模，恰恰是最先没有增长空间的那个。

接下来几年有一种可能，是数据工作不再像采集，而更像测量。问题不是我们还能拿到什么，而是手上这些数据究竟值多少，其中哪些部分在真正起作用，以及如果我们判断错了要怎么才能知道。这份清单最让人不安的地方在于，其中有多少条是没有人在自己的语料上量过的数字，以及其中又有多少条量起来其实并不贵。
