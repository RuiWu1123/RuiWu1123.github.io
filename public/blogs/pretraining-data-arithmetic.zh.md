有一个数字能把预训练数据这个方向上几乎所有问题重新框一遍。[Villalobos 等人](https://arxiv.org/abs/2211.04325)估计，indexed web 上文本的有效存量大约是 4×10¹⁴ 个 token；而前沿训练集在 2024 年前后处在 10¹³ 这个量级，每年增长约 0.38 个数量级。把这条增长曲线外推到这个存量上限，交点落在 2028 年，正好在论文自己给出的 2026 到 2032 这个区间的中间。

![The token budget](blogs/images/pdata-budget.svg?v=1)

那条虚线不是网上文本的总量。原始的 indexed web 文本估计有 510T token，Common Crawl 是 130T；4×10¹⁴ 这个数是过完质量过滤之后剩下的部分，按 10% 到 40% 的留存率算，再乘上一个允许重复使用的 5 倍系数。这个乘积里几乎每一项，数据团队都能动。供给一旦固定，这个方向上所有的技术就都在回答同一个问题：手上已有的每个 token，能榨出多少可用信号。

过滤、去重和质量分类器决定**哪些** token 值得花算力；配比决定各类数据占多大**比例**；重复决定同一份数据用几**遍**；课程决定这些数据**什么时候**出现。合成数据试图抬高上限本身。而数据污染，是前面任何一步做错了却没被发现时，最后送来的账单。

## 一、每一代语料到底新增了什么

开放 web 语料是一条有清晰代际的链条，每一代加进来一个机制，各代语料的规模则说明力气花在了哪儿。

![Published sizes of open pretraining corpora](blogs/images/pdata-corpora.svg?v=1)

C4 出自 2019 年的 T5 工作，大约 750 GB 英文文本，做法是拿启发式规则去处理 2019 年 4 月的单个 Common Crawl 快照：删掉不以终止标点结尾的行，删掉命中脏词表的文档，只留语言检测判为英文的部分，去掉重复行。这套模板立住了，而两年后那篇[文档化论文](https://arxiv.org/abs/2104.08758)才是今天还有人争论它的原因。作者拿方言分类器去看 blocklist 到底删掉了什么，发现非裔美国英语（AAE）的删除率是 42%，西语裔英语是 32%，而白人美国英语（WAE）只有 6.2%。留下来的语料里 97.8% 是 WAE，AAE 占 0.07%。一个为了滤掉色情内容而设计的规则，滤掉的是语言社群，而这件事两年没人发现，因为没人去量。

[CCNet](https://arxiv.org/abs/1911.00359) 贡献的是"质量可以打分而不只是匹配"这个想法。在 Wikipedia 上训一个 KenLM n-gram 模型，用它给每篇 Common Crawl 文档算困惑度，再按 head、middle、tail 分三档。第三节里所有东西的祖先都在这儿：它把"好文本长什么样"这条规则，换成了一个关于好文本的模型。

The Pile 走的是反方向，把 22 个精选子集拼成 825 GiB，而它真正留下来的东西其实是 domain 标签，不是文本本身。因为每篇文档都带来源，The Pile 成了配比研究的标准试验台，它默认的 22 域权重也就成了第四节里每种方法都要对比的基线。

[RefinedWeb](https://arxiv.org/abs/2306.01116) 提出的论断是精选没必要：只要把 web 数据过滤和去重做到位，就足以训出强模型，甚至明显超过当时在 The Pile 上训练出的最好模型。它的 pipeline 就是今天的标准形状，按顺序是：用成人内容黑名单加一套打分系统做 URL 过滤，用 trafilatura 抽正文，用 fastText 做语种识别，套一遍 Gopher 启发式规则和他们自己的逐行修正，最后做 MinHash 模糊去重和精确子串去重。他们从 Common Crawl 里拿到 5T token，公开了其中 600B。

再往后是透明化的一代。RedPajama 复刻 Llama 1 的配方做到 1.21T token；SlimPajama 在它上面跑全局 MinHashLSH，13-gram、Jaccard 阈值 0.8，删掉 49.6% 的字节，剩下 627B。[Dolma](https://arxiv.org/abs/2402.00159) 公开了 3T token，是从大约 200 TB 原始文本清洗到 11 TB 得来的，工具链和 ablation 一并放出。[FineWeb](https://arxiv.org/abs/2406.17557) 处理了 2013 年夏天到 2024 年 4 月的 96 个 Common Crawl 快照，得到 15T token，后来扩到 18.5T 以上。[DCLM](https://arxiv.org/abs/2406.11794) 则把 240T token 的 Common Crawl 标准化成一个 benchmark，配 53 个下游评测、412M 到 7B 的模型规模，让数据 curation 变成了一件有排行榜的事。

池子是巨大的，而人们真正拿去训练的语料要小上一到两个数量级。

## 二、去重，以及 MinHash 为什么长成一条 S 曲线

web 文本里的重复不是个可以忽略的零头。[Lee 等人](https://arxiv.org/abs/2107.06499)在 C4 上跑近似重复检测，发现 3.04% 的训练样本在训练集里另有一份近似重复，RealNews 上这个比例是 13.63%，而极端个例比平均值更离奇：他们从 C4 里删掉了"一句 61 个词的英文句子，重复了六万多遍"。训练集与测试集的重叠"影响了标准数据集验证集的 4% 以上"，所以重复会悄悄虚抬评测分数。而去重"让模型逐字吐出记住的文本的频率降到十分之一"，所以模型逐字背出训练文本，主要也来自重复。

精确去重就是一张哈希表，精确**子串**去重则是在拼接后的整个语料上建后缀数组，它能找出所有超过某个长度的重复片段，完全不管文档边界在哪。这两种都抓不住真正麻烦的情况：两篇文档只差一个模板化的页头、一个时间戳，或者一句被改写过的话。

标准答案是 MinHash 配 locality-sensitive hashing。把每篇文档表示成它的 k-gram shingle 集合。对 shingle 全集的一个随机置换 π，π 在集合 A 上的最小值等于它在 B 上最小值的概率，恰好就是 Jaccard 相似度 J(A,B)：因为 A ∪ B 上的 argmin 等概率落在并集的任一元素上，而两个最小值相等，当且仅当它落进交集。于是 m 个独立置换构成的签名就是 m 次 Bernoulli(J) 抽样，比较签名等于在估计 Jaccard，全程不需要真的去比文档。

LSH 把这个估计变成一个可检索的结构。把 m 行签名切成 `b` 段、每段 `r` 行，m = b·r，每段各自建索引。两篇文档在某一段里撞上，要求这 `r` 行全部相同，在真实相似度 `s` 下概率是 `s^r`，于是至少撞上一段的概率是

$$
P(\text{candidate}) \;=\; 1 - (1 - s^{r})^{b}
$$

这是关于 `s` 的一条 sigmoid，拐点在 `(1/b)^{1/r}` 附近，而真正的旋钮就是这个拐点。它不是你设定的相似度阈值，而是你把哈希预算切成 `b` 段 `r` 行之后**被动得到**的阈值。

![The LSH S-curve, measured and predicted](blogs/images/pdata-lsh.svg?v=1)

曲线是公式，点是量出来的：我构造了重叠度可控的文档对，在 5-gram shingle 上用 180 个置换算真实的 MinHash 签名，切成 20 段每段 9 行建索引，再记录每一对实际有多少比例被捞成候选。右边那栏把同样 180 个哈希拆成五种不同的因数分解。这五行之间语料没有任何变化，但 45 段 × 4 行会把 Jaccard 0.39 的文档对也捞进来，5 段 × 36 行则连 0.96 以下的都不看一眼。一条去重 pipeline 有多激进，取决于一个整数怎么分解，而大多数人不会往这儿找原因。

除了 `(b, r)`，还有两个选择同样要紧。一个是粒度：文档级、段落级和行级去重删掉的东西差别很大，SlimPajama 的 ablation 也表明跨来源的全局去重和来源内部的局部去重不可互换。另一个是语义：[SemDeDup](https://arxiv.org/abs/2303.09540) 用预训练模型给文档做 embedding，聚类之后在簇内删掉近邻，能抓到那些一个 shingle 都不共享的重复对。在 LAION 的一个子集上，它"删掉 50% 的数据而性能几乎不掉，训练时间直接减半"。它自己在 C4 上的结果要克制得多，超过此前的去重方法、带来 15% 的效率提升，作者把差距归因于 C4 本来就已经被部分精选过了。

## 三、质量过滤：从规则到分类器

Gopher 的 pipeline 立起了基于规则的标准：按词数、平均词长、符号与词的比例、以项目符号开头或以省略号结尾的行占比这类文档统计量来过滤，删掉文档内部的重复文本，再做文档之间的去重，最后删掉与测试集重叠的文档。今天每一条 pipeline 都在重新实现这套东西的某个版本，各家的阈值也各有出入。更要紧的是这些过滤器叠在一起会发生什么，而 Dolma 把它量出来了。

![What survives a composed pipeline](blogs/images/pdata-funnel.svg?v=1)

每一级的比率是论文里的，连乘是我做的：Gopher 的整套规则标记了 15.23% 的 UTF-8 字符待删，C4 的无标点规则标记了 22.73%，模糊加精确去重大约删掉一半，而一个只保留最高十分之一的模型分类器又删掉九成。乘起来，抽出来的文本大约剩 3%。这才是 web pipeline 真实的形状：它不是一个过滤器，是一条存活概率。

C4 的 NoPunc 规则**单独使用**时，在困惑度和下游任务上都优于 C4 的整套规则，也优于 Gopher 的整套规则；最好的配置是 Gopher 全套加上 C4 NoPunc。规则更多不等于质量更好，而这套规则里最粗暴的那一条，贡献了大部分收益。

2024 年的共识从规则转向了学出来的分类器，而两个参考实现挑了完全不同的正例来源。DCLM 训了一个 fastText 分类器，正例是指令格式的文本，具体来说是 OpenHermes 2.5 和 r/ExplainLikeImFive，负例是随机网页。FineWeb-Edu 走的是另一条路：让 Llama-3-70B-Instruct 给 46 万个页面的教育价值打分，蒸馏成一个小分类器，在阈值 3 处达到 F1 82%，再拿它去给全部 15T token 打分，花掉 6000 个 H100 小时。两条路都成立。FineWeb-Edu 报告一个 1.71B 模型在 350B token 上训练后，MMLU 从 33% 升到 37%，ARC 从 46% 升到 57%。DCLM 的结论更强，也把一般原则挑明了："model-based filtering is key"，DCLM-Baseline 让 7B 模型在 2.6T token 上拿到 64% 的 5-shot MMLU，比此前最好的开源数据模型高 6.6 个点而算力少 40%，算力只有 Llama 3 8B 的六分之一。

两组人都没有定义质量，都是挑了一个自己相信与质量相关的 proxy 语料，而过滤器会继承这个选择的全部性质。"读起来像 ELI5 回答的文本"和"一个 70B 模型判为有教育价值的文本"是两个不同的目标，也没有理由认为其中哪一个，就是你想要的那个目标，尤其是当这个模型之后还要 post-train 成 agent 的时候。[A Pretrainer's Guide](https://arxiv.org/abs/2305.13169) 把随之而来的取舍讲明了：把毒性从预训练里滤掉，会削弱模型**识别**毒性的能力。所以至少在这一个维度上，质量和能力指向相反的方向，而没有理由认为只有这一个维度如此。

## 四、配比，当成一个优化问题

有了 domain，就有了比例，而比例是数据工作里唯一一块看上去真有明确目标函数的地方。各种方法的差别，主要在于它们愿意假设多少。

DoReMi 把它当成一个 minimax 问题。用 [group distributionally robust optimization](https://arxiv.org/abs/2305.10429) 训一个小 proxy 模型：模型这一侧最小化相对参考模型的最坏情况超额损失，域权重则是内层最大化那一侧的副产物；再把这组权重拿去训一个大 30 倍的模型。从 280M 的 proxy 到 8B 的目标，这套做法"把平均 few-shot 下游准确率相对使用 The Pile 默认域权重的基线提升了 6.5 个百分点，并且只用 1/2.6 的训练步数就达到了基线准确率"，也就是 75k 步对 200k 步。全部 22 个 Pile 域的困惑度都改善了，**包括那些被这个方法降权的域**。学出来的权重一点都不温和。Pile-CC 从 0.1121 升到 0.6057；ArXiv 从 0.1052 掉到 0.0036；PubMed Central 从 0.1071 掉到 0.0046。把一个域的权重砍到三十分之一，反而让这个域自己的困惑度变好了，因为一个域最需要的是一个已经学会语言的模型，而通往那里最快的路是更多 web 文本。

[DoGE](https://arxiv.org/abs/2310.15393) 把鲁棒性目标换成了一阶目标。给每个域打分，分数是它的梯度与全部域梯度之和的内积，哪个域的梯度方向更接近"对所有域都有帮助"的方向，它就拿到更高的权重；权重按 mirror descent 更新。这个分数可以拆成跨域对齐加上该域自己的梯度范数，所以"难度"和"有用性"在里面是纠缠的，但这个框架把配比和 influence function 直接接上了。它报告用 82M 的 proxy 服务 684M 的目标，5-shot 推理上比均匀混合高 1.7 个点。

[RegMix](https://arxiv.org/abs/2407.01492) 干脆不去建模机制。训 512 个 1M 参数的模型、每个 1B token，混合比例从一个偏向极端的 Dirichlet 里采样，然后拟合一个从混合比到验证损失的回归器，再去优化这个回归器。这里 LightGBM 大幅胜过线性回归（预测 1B 模型排序时 Spearman 97.1 对 88.0），这件事本身就说明，单纯形上的损失曲面离线性差得远。预测出的最优混合，在 64 个各训 25B token 的 1B 候选模型里排第一，而 512 个 proxy 加起来只占单次 1B 训练约 2% 的 FLOPs。它有两个发现是普遍成立的。一是 web 语料，而不是那些人人称之为高质量的来源，与下游性能的相关性最强，这从一条完全不同的技术路线上印证了 DoReMi 的 Pile-CC 结果；二是"data mixture effects transcend scaling laws"，意思是小规模上找到的混合排序能延续到大规模，即便绝对损失值不能。

[Data Mixing Laws](https://arxiv.org/abs/2403.16952) 给这个曲面配了一个函数形式。记 `r_j` 为训练域 `j` 的比例，`L_i` 为验证域 `i` 上的损失，

$$
L_i(r_1, \ldots, r_M) \;=\; c_i + k_i \exp\Big(\sum_{j=1}^{M} t_{ij}\, r_j\Big)
$$

其中 `c_i` 是任何混合都消不掉的那部分损失，`k_i > 0` 是尺度，`t_ij` 是训练域 `j` 与验证域 `i` 之间的交互；`t_ij` 为负表示 `j` 对 `i` 有帮助。指数落在求和号外面，参数量因此随域数线性增长，而不是平方增长。总目标是 `Σ_i s_i L_i`，`s_i` 是验证集的域比例。在小规模上拟合它，再和训练步数、模型规模两条独立的 scaling law 套在一起，就能用小规模实验预测大规模的损失；收益是给 1B 模型在 100B RedPajama token 上找到的混合，"达到了默认混合多训 48% 步数才能达到的性能"。

下面是一个三域的实例，在整个单纯形上求值，交互符号取得合理，其中一个域在验证集里权重更高。

![The loss surface over a three-domain simplex](blogs/images/pdata-mixing.svg?v=1)

有两个特征是普遍的。一是最优点在内部，而且不是均匀混合，这正是自动配比存在的全部理由；二是这个曲面在最优点附近很平、靠近边界很陡：均匀混合与最优之间差 0.0129 nat，按 C4 的 scaling law 折算，相当于在 100B token 的预算下多给 21% 的 token，而走到单纯形的角上，代价要大得多。配比值得做，但不值得为小数点后第三位纠结。

[CLIMB](https://arxiv.org/abs/2504.13161) 处理的是上面所有方法共同的前提，也就是你手上有 domain 标签。Common Crawl 并不自带标签。CLIMB 把文档 embedding 之后聚类，把 proxy 加 predictor 的搜索跑在簇权重而不是来源权重上，再用找到的混合继续训练一个 1B 模型 400B token，比 Llama-3.2-1B 高 2.0 个点。簇不是 domain：配比这套形式化里，没有任何一处要求这个划分对人类有意义。

## 五、重复：同一个 token 能用几次

到目前为止的一切都默认每个 token 只看一遍。池子一旦固定，这个默认就变成了一个选择，而 [Muennighoff 等人](https://arxiv.org/abs/2305.16264)用四百多次训练量了它的代价，参数从 10M 到 9B，token 最多 900B，epoch 最多 1500。

记 `U_D` 为 unique token 数，`R_D = D/U_D − 1` 为重复次数，于是 `R_D = 0` 表示只跑一个 epoch。那么**有效数据**，也就是能产生同样损失所需要的新鲜数据量，是

$$
D' \;=\; U_D + U_D\, R_D^{*}\left(1 - e^{-R_D / R_D^{*}}\right)
$$

在超额参数 `R_N` 下，有效参数 `N'` 有一个对称的表达式。拟合得到 `R_D* = 15.39` 和 `R_N* = 5.31`，作者把它们描述为重复数据和超额参数各自的半衰期。关于重复的一切，都从这条指数的形状里推出来。

![What repeated epochs are worth](blogs/images/pdata-repetition.svg?v=1)

四个 epoch 换来 3.73 个 unique token 的价值，是四个 epoch 全用新数据时的 93%，这就是论文那句"重复至多约 4 个 epoch，损失相比全新数据几乎没有变化"的定量形式。十六个 epoch 换来 10.58，是 66%。而这条曲线有一个不可逾越的上限 `1 + R_D* = 16.4`：任何固定语料，无论怎么重复，价值都不会超过它自身的 16.4 倍。到第 44 个 epoch，这 16.4 里你已经收了 15.45，而边际的那个 epoch 只值 0.063 个 unique token，是第一个 epoch 的十六分之一。另外论文观察到训了 44 个 epoch 的模型实际上会发散，所以这条曲线的后段描述的是一个你不会去运行的区间。

流传很广的那句"到 40 个 epoch 左右收益归零"并不在论文里。论文说的是有意义的收益延伸到大约 16 个 epoch，"越过之后收益衰减得极快"。40 是二手转述；上面那个公式才是原始对象，而它说的事情略有不同，也有用得多。

## 六、数据固定时，算力该怎么分

把重复曲线放回算力预算里，它就变成了一个决策。Muennighoff 等人把 `N'` 和 `D'` 代进一个在 C4 上重新拟合的 Chinchilla 形式，得到

$$
L(N', D') \;=\; 1.87 + \frac{521}{N'^{\,0.353}} + \frac{1488}{D'^{\,0.353}}
$$

[Chinchilla](https://arxiv.org/abs/2203.15556) 假设 unique 数据无限，结论是参数和 token 应该同比增长，大约每个参数配 20 个 token。而在 unique token 预算固定的前提下，这条建议就不再适用了，因为在质量不变的前提下，"更多 token"已经拿不到了。

那就把 `U_D` 固定在 1T unique token，扫算力预算 `C = 6ND`，对每个预算在模型规模上搜索，epoch 数由 `D / U_D` 直接给出。

![Optimal epochs against compute at a fixed unique-token budget](blogs/images/pdata-allocation.svg?v=1)

在 10²³·⁵ FLOPs 以下，最优解一次都不重复：每多一份算力都花在参数上，epoch 数始终是 1。越过这一点之后，参数规模已经远超这份 unique 数据所匹配的规模 `U_N`，`R_N` 那一项的惩罚超过了 `R_D`，于是最优解开始买 epoch。到 10²⁵ FLOPs，最优配置是 229B 参数、在数据上过 7.3 遍。

这个门槛随你手上的数据移动，而且规律很干净：100B unique token 在 10²¹·⁵ 开始重复，1T 在 10²³·⁵，10T 在 10²⁵·⁵。外推到公开人类文本的全部有效存量，也就是 4×10¹⁴ token，重复大约在 10²⁷ FLOPs 开始划算。而 Villalobos 等人给出的、模型耗尽这份存量时对应的算力是 5×10²⁸ FLOPs。这两个数字相差大约两个数量级，这才是"数据墙"这个词的实际内容：它不是一道断崖，而是越过之后，额外的算力买到的是 epoch 和参数，而不是新的信息。

## 七、课程：不是所有 token 都该在同一时刻到场

第四节那样提出的配比，要的是整个训练过程共用一组比例。有两个各自独立的工业结果说明，这样做会白白丢掉一部分收益。

Llama 3 在最后 40M token 上把学习率线性退火到零，同时上采样极高质量的来源，并对退火阶段的 checkpoint 做平均。退火让一个 8B 模型"在 GSM8K 和 MATH 验证集上分别提升了 24.0% 和 6.4%"，而这个 ablation 退火用的是这两个 benchmark 的**训练集**；对 405B 模型，提升可以忽略。机制大概是小模型需要这个示范，而大模型已经自己泛化到了。

同一篇论文还把退火变成了一件测量仪器。要评估一个候选数据集，取一个训到 50% 的 8B checkpoint，在 40B token 上退火到零，其中候选数据集占 30% 权重、默认混合占 70%，然后读取变化量。这样每个候选只花一次短训练，而不是每个候选跑一遍 scaling law。

[OLMo 2](https://arxiv.org/abs/2501.00656) 把同样的直觉固化成了一个有名字的阶段。Stage 1 大约 3.9T token，其中超过 95% 是 web。Stage 2 他们叫 midtraining，从一个约 843B token 的高质量池子里取样，这个池子由过滤后的 web、学术文本、Q&A、指令数据和合成数学题拼成，采样到 50B、100B 或 300B，其中 DCLM 过滤过的 web 仍然供应大约一半的预算。7B 上他们跑三次数据顺序不同的 50B 退火，然后把权重平均。

![Midtraining, before and after](blogs/images/pdata-midtrain.svg?v=1)

这些是论文里的数字，不是我量的。GSM8K 在 7B 上从 24.1 到 67.5，13B 上从 37.3 到 75.1；DROP 从 40.7 到 60.8；十项 benchmark 的平均在 7B 上移动 10.6 分，13B 上 10.3 分。十分之一的 token 预算，放在最后花，对平均分的推动超过了绝大多数架构改动能带来的提升。他们也给这套评估协议起了名字，叫 microannealing，就是把 Llama 3 那套测量方法在每个候选数据集上各跑一遍。

于是单一的全局混合就成了一个错误的对象。这些结果描述的是一张时间表，而所有配比方法都不在时间表上优化，它们优化的是一个点。

## 八、合成数据，以及它失效时的形状

如果人类文本的存量是固定的，那么最直接的一步就是自己造。这里的证据确实是两面的，而这两面通常被拿来互相反驳，实际上它们说的不是同一件事。

有效的那一面是 [phi-1](https://arxiv.org/abs/2306.11644)：1.3B 模型，训练数据是 6B token 的过滤后代码，加上约 1B token 由 GPT-3.5 生成的教科书与习题，8 张 A100 训 4 天，HumanEval pass@1 达到 50.6%，MBPP 55.5%；350M 的版本也还有 45%。它的成分要读仔细，因为经常被说错：那 6B 是从 The Stack 和 StackOverflow 里过滤出来的**代码**，不是通用 web 文本，而合成部分大约占七分之一的 token。[WRAP](https://arxiv.org/abs/2401.16380) 提出的主张对数据受限的世界更直接，它用一个指令微调过的模型把 web 文档改写成不同风格，报告在 C4 上预训练加速约 3 倍，在算力相同的条件下 Pile 各子集的困惑度改善超过 50%，13 个任务的 zero-shot 平均提升超过 2%。改写是在用算力换一种行为上接近 unique 数据的数据，而 unique 数据恰恰是第五节说的那种稀缺资源。

失效的那一面是 Nature 上关于 [model collapse](https://www.nature.com/articles/s41586-024-07566-y) 的结果："不加区分地把模型生成的内容用于训练，会在所得模型里造成不可逆的缺陷，原始内容分布的尾部会消失。"机制比这个名字听起来简单。用极大似然在 `n` 个样本上拟合一个高斯，从拟合出的分布里抽 `n` 个新样本，再拟合，如此往复。每一步的均值估计单看都是无偏的。但极大似然的方差估计恰好只有真值的 `(n−1)/n`，于是

$$
\mathbb{E}[\sigma_g^2] \;=\; \left(\frac{n-1}{n}\right)^{g}\sigma_0^2
$$

而方差是一个非负鞅，必然收敛；极限是零。

![Variance under recursive refitting](blogs/images/pdata-collapse.svg?v=1)

取 `n = 100`、300 条独立链，量出来的平均方差与那条几何衰减严丝合缝，而实际后果是那条绿线：第 `g` 代模型分配到**原始**分布 ±2σ 之外的概率质量，从第 0 代的 4.6% 掉到第 100 代的 0.08%，到第 200 代在数值上已经是零。任何单独一步都没有出现病态。坍缩是有限样本被迭代之后必然发生的事，单代内部再小心也拦不住。

所以这两面并不冲突。坍缩说的是闭环，而 phi 和 WRAP 说的是锚定在真实数据上的单代合成。区分它们的条件是真实数据有没有持续进入这个循环，而这个条件是可以检验的，不是一个哲学问题。

## 九、污染，以及 n-gram 去污染为什么不管用

这篇文章里的每一个论断都是一个 benchmark 数字，所以最后一个问题是这些数字到底还算不算数。工业界的标准答案是 n-gram 去污染：凡是与测试题共享某个 n-gram 的训练文档就删掉，`n` 通常取 8 到 13。

[Yang 等人](https://arxiv.org/abs/2311.04850)证明这一步轻易就能绕过，而且不需要有人蓄意为之。把一道测试题改写一遍，或者翻译一遍，n-gram 重叠就归零了，而这道题在评测意义上还是同一道题。他们的主结论是"一个 13B 模型可以轻松过拟合一个测试 benchmark，达到与 GPT-4 相当的高分"；在改写过的 MMLU 上，Llama-2 7B 从 45.3 升到 88.5，13B 从 54.8 升到 89.9。

![n-gram overlap between a benchmark item and its paraphrase](blogs/images/pdata-contamination.svg?v=1)

这是一道算术应用题和它的一个改写版之间量出来的重叠，任何像样的模型对这两道题都会给出同样的答案。unigram 重叠是 38%，bigram 15%，trigram 3%，从 4-gram 开始就是精确的零。一个 n = 13 的去污染过滤器不只是漏掉了这一对，它根本看不见这一对；n = 8、n = 5 时同样如此。而能抓住改写的那个 n，小到会把语料删掉大半。

污染在真实语料里已经是量出来的，不是假设出来的。同一份工作发现 HumanEval 有 8.5% 与 RedPajama-Data-1T 重叠、15.9% 与 StarCoder-Data 重叠、18.9% 与 The Stack 重叠。这些还只是 n-gram 匹配**看得见**的那部分。

[Min-K% Prob](https://arxiv.org/abs/2310.16789) 要回答的是某段文本是否在预训练数据里，而且不能访问语料、也不能用参考模型：取文本中概率最低的 k% 个 token，对它们的对数似然求平均，依据是没见过的文本里会有模型赋予极低概率的离群 token。WIKIMIA 用 Wikipedia 的编辑时间戳构造成员关系的金标准；在这个 benchmark 上，Min-K% Prob 达到 0.72 的平均 AUC，此前最好的方法是 0.67，论文把这个改进写成 7.4%，这是相对值，不是 7.4 个 AUC 点。0.72 的 AUC 是一个真实的信号，也是一个不合格的检验。对一份不是自己构建的语料，我们目前无法验证某个评测是否干净，而多数已发表的比较，两边模型的污染状况都是未知的。

## 十、这些算术合起来说明什么

把这些数字放到一处，形状就出来了。有效存量在 4×10¹⁴ token 附近，而数据集规模在 2028 年前后追上它。叠起来的过滤只留下抽取文本的百分之几，其中分类器那一级干了大部分活，而它由一个任意挑选的正例集合定义。去重的激进程度取决于一个整数分解，多数团队从来没调过它。配比大约值一个 token 预算的 20%，再多没有了。重复至多值你 unique 语料的 16.4 倍，而对 1T 的池子它在 10²³·⁵ FLOPs 变成正确选择，对整个 web 则是 10²⁷。十分之一的预算放在最后花，值 10 分的 benchmark 平均分。合成有效的前提，恰好是真实数据持续进入循环。而上面这些测量，目前都没法拿一个已知干净的 benchmark 去验证。

五个最大的杠杆里有四个，也就是分类器正例、去重粒度、混合比例和 midtraining 时间表，都是某个人当初定了一次、之后很少回头看的选择。而吸引了全部注意力的那一个，语料规模，恰恰是正在撞墙的那个。接下来几年有一种可能，是数据工作不再像采集，而更像测量：问题不是我们还能拿到什么，而是手上这些数据究竟值多少，以及我们怎么才能知道。
