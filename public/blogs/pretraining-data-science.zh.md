一次预训练启动之前，数据上至少有三件事要定下来：整份语料过几遍，各个来源之间怎么配比，过滤和去重做到什么程度。

第一件事上，已发表的答案就对不上。Hernandez 等人把 0.1% 的语料重复一百遍，800M 的模型就退化到 400M 的水平；Muennighoff 等人把整份语料重复四遍，loss 只高 0.5%；Pythia 在去重过的 Pile 上跑了 1.5 个 epoch，连去重有没有用都没测出来。第二件事也一样：DoReMi 说它训出来的模型比按 Pile 默认权重训的高 6.5 个点；Aioli 发现包括 DoReMi 在内，没有一种配比方法能稳定赢过「每组等量采样」。

这些数字都没错，不一样的是产生它们的实验。所以下面每给出一个结论，我都会把产生它的那次运行一起写出来：多少个模型，多大，训了多少 token，跟什么 baseline 比，用什么指标，跑了几个 seed。

## 1. 坐标系，以及数据受限时要做的修正

Chinchilla 那条「参数量和 token 数等比例放大」的建议，前提是 token 能按任意数量、以不变的质量买到。把这个前提去掉，建议就反过来：语料固定的时候，多出来的 compute 应该先加 epoch 再加参数，而且前四个 epoch 几乎不要钱。这两条相反的建议出自同一个 loss 曲面。

[Chinchilla](https://arxiv.org/abs/2203.15556) 把它拟合成

$$
L(N, D) \;=\; E + \frac{A}{N^{\alpha}} + \frac{B}{D^{\beta}}
$$

`N` 是参数量，`D` 是训练 token 数，`L` 是留出文本上的交叉熵，单位 nat/token。`E` 是一个理想的生成过程在这份数据分布上仍然要付的代价，也就是自然语言文本的熵。$A/N^{\alpha}$ 是一个训练到最优的 `N` 参数 transformer 与这个理想之间的差距。$B/D^{\beta}$ 是只训了 `D` 个 token 就停下、没有训到收敛所多付的那部分。

论文附录 D.2 把这三项读成一个风险分解：Bayes risk，一个随假设空间大小变化的 approximation 项，以及在有限样本上跑一遍带来的 stochastic approximation error。这个读法是盖在一条拟合曲线上的，而拟合分不开 approximation error、优化没到位、以及 transformer 这个函数类特有的部分，所以它是作者的解释，不是这五个常数能证明的事。

setup 是这样：400 多个模型，参数量 70M 到 16B，训练量 5B 到 500B token；没有 baseline，这里不比较任何东西；指标是训练分布上的 loss，不是留出集上的；没有重复 seed。论文给的置信区间来自对运行做 80% 子采样再重拟，不是把哪个模型训了两遍。

这五个常数就是这么拟合出来的。Chinchilla 取前两种方法里每次运行的最终 loss，用 L-BFGS 最小化预测 log loss 与实测 log loss 之间的 Huber 损失，$\delta = 10^{-3}$，初值取自 `α, β ∈ {0, 0.5, …, 2}` 以及 `A`、`B`、`E` 的对数形式所构成的网格。放到 log 空间里做，三项之和就变成一个 log-sum-exp，拟合不会被 loss 最大的那些运行主导。结果是 `E = 1.69`、`A = 406.4`、`B = 410.7`、`α = 0.34`、`β = 0.28`。

被所有人引用的那条规则，从这五个数字推出来只要一步。取训练 FLOPs 的常用近似 `C ≈ 6ND`，把 `D = C/(6N)` 代进曲面，再对 `N` 求极小：两个可变项变成 $A/N^{\alpha}$ 和 $B(6N/C)^{\beta}$，一个随 `N` 降、一个随 `N` 升，令导数为零就得到 $N_{\mathrm{opt}} \propto C^{\beta/(\alpha+\beta)}$、$D_{\mathrm{opt}} \propto C^{\alpha/(\alpha+\beta)}$。代入 `α = 0.34`、`β = 0.28`，`β/(α+β) = 0.28/0.62 = 0.45`，`α/(α+β) = 0.55`；论文用未取整的拟合值报的是 0.46 和 0.54，另外两种完全不写函数形式的方法给的是 0.50/0.50 和 0.49/0.51。这几个指数都在 0.5 附近，这就是「参数量和 token 数等比例放大」的全部内容。

[Muennighoff 等人](https://arxiv.org/abs/2305.16264) 把这个假设去掉，重新推了一遍曲面。他们的 setup：400 多个模型，10M 到 9B 参数，总计最多 900B token、最多 1500 个 epoch，比较对象是同架构的单 epoch 运行以及 Chinchilla 自己那套分配。指标是 C4 留出集上的测试 loss，外加 19 个下游任务的重标定平均分；没有报告重复 seed。全部是 GPT-2 架构和 tokenizer，跑在 C4 的子集上，cosine schedule 在训练过程中衰减 10 倍，并且刻意不做 early stopping，好让 overfitting 显出来。这些子集是嵌套的，所以 unique data 更少的那一组看到的一定是更大那一组的子集。报留出 loss 这一点本身就和 Chinchilla 不同，后者报的是训练 loss。

他们把 Chinchilla 的 `D` 拆成两半。$U_D = \min\{D_C, D\}$ 是数据预算 `D_C` 实际能提供的 unique token 数，$R_D = D/U_D - 1$ 是重复次数，单个 epoch 就是 $R_D = 0$。他们要的是有效数据量 `D'`，也就是换成全新数据、能达到同样 loss 所需要的量。

推导是一个等比数列。假定每过一遍某个 token，模型都从它剩下的信息里取走固定的一份，于是第 `k` 遍的价值是第一遍的 $(1-\delta)^{k}$ 倍。把 `R_D` 次重复加起来，

$$
\begin{aligned}
D' \;&=\; U_D + (1-\delta)U_D + (1-\delta)^{2}U_D + \cdots + (1-\delta)^{R_D}U_D \\[2pt]
     &=\; U_D + \frac{(1-\delta)\,U_D\left(1 - (1-\delta)^{R_D}\right)}{\delta}
\end{aligned}
$$

再令 $R_D^{*} = (1-\delta)/\delta$。$\delta$ 很小的时候 $1/R_D^{*} \approx \delta$，而 $(1-\delta) \approx e^{-\delta} \approx e^{-1/R_D^{*}}$，上面那一串就化简成

$$
D' \;=\; U_D + U_D\, R_D^{*}\left(1 - e^{-R_D / R_D^{*}}\right)
$$

所以 $R_D^{*}$ 就是每次重复的衰减率 $\delta$ 换了个写法。写成 $(1-\delta)/\delta$ 之后读起来像半衰期，作者后面也确实这么叫它。拟合出的 $\delta \approx 6\times 10^{-2}$，对应的就是 $R_D^{*} = 15.39$。参数那一侧同样处理：$U_N = \min\{N_{\mathrm{opt}}, N\}$，$R_N = N/U_N - 1$。

这个拟合搭在 Chinchilla 的拟合之上。他们先在 C4 上重拟一遍 Chinchilla 的形式，用 Chinchilla 自己的 54 个数据点，并强制 `α = β`，得到 $L = 1.87 + 521/N^{0.353} + 1488/D^{0.353}$。随后他们固定这些常数，只拟合 $R_D^{*}$ 和 $R_N^{*}$，样本是他们自己的 182 次运行，参数量 7M 到 9B，epoch 数 1 到 500，目标函数还是同一个 log 空间里的 Huber，L-BFGS 的初值网格取 `{0, 4, …, 20}²`。结果是 $R_D^{*} = 15.39$、$R_N^{*} = 5.31$，作者把它们叫作重复数据和多余参数各自的半衰期。

![多跑一个 epoch 值多少](blogs/images/pdsci-repetition.svg?v=1)

这张图是我按上面那个表达式算的。四个 epoch 相当于 3.73 份语料，广为流传的「四个 epoch 之内基本免费」就是从这里来的；论文自己举了个例子：8.7B 模型在 44B unique token 上跑完四个 epoch，validation loss 只比同样模型在 178B unique token 上高 0.5%。这个 0.5% 是 loss 的相对差，不是 accuracy 点，没法直接摆到 DataDecide 那把两点的尺子上，但两次运行的差距比 DataDecide 分辨不开的那些语料之间的差距还小。十六个 epoch 相当于 10.58 份。这条曲线的上限是 $1 + R_D^{*} = 16.4$：无论怎么重复，一份语料的价值都到不了自身的 16.4 倍以上。图里的边际那一列是我自己推的：那个指数形式意味着第 k 个 epoch 相对于一个新 token 的价值是 $e^{-(k-1)/15.39}$。论文只给了上限和半衰期，没有逐 epoch 列过表。

后面还有两个推论。因为 $R_N^{*} < R_D^{*}$，多余参数掉价比重复数据更快，所以在数据受限的时候，多出来的 compute 应该先花在 epoch 上而不是参数上，这和 Chinchilla 的等比例建议正好相反。他们在大尺度上验证过：在 9.3×10²¹ FLOPs、25B unique token 的条件下，他们的前沿给出 6.34B 参数配 242B 总 token，Chinchilla 给出的是 8.67B 配 178B，而更小的那个 loss 更低。也就是参数量少 27%，换成在同样 25B unique token 上多跑 36% 的 token。

这个上限本身还能抬高，办法是改变「什么算语料」。他们从 The Stack 里混入 Python，发现即使只在自然语言上评测，code 占比到 50% 都不掉点，因此 code 相当于把有效 token 数翻了一倍。合起来的建议写得很直接：先用 code 把数据量翻倍，再重复四遍，得到「8 倍的训练 token，效果预期等同于真有 8 倍的 unique data」。他们十九项评测里有两项只要加了一点 code 就立刻变好：bAbI 在 10% code 时从 0.0 到 12.5，WebNLG 从 4.8 到 9.5，作者认为是 code 让模型学会了长程的状态追踪。

## 2. 一个数据实验凭什么可信

给预训练语料排序，用一个小 proxy 模型比跨几个尺寸拟合 scaling law 更划算，同等 compute 下前者不输，而且 proxy 可以很小。proxy 指专门用来排序的小模型，target 是你最终真正要训的那个大模型。真正卡住这类实验的不是 proxy 的大小，而是噪声：在 1B 的 target 上，同一个配方换个 seed 再训一遍，accuracy 可以差两个点，比大多数已发表的数据处理收益还大。

[Pythia](https://arxiv.org/abs/2304.01373) 就是为了让这一步能被人审计才做的。十六个模型，八个尺寸从 70M 到 12B，每个模型精确训练 299,892,736,000 个 token，比较的是 Pile 和 MinHash 去重后的 Pile，指标是常规的语言模型 benchmark，每个配置一个 seed。MinHash 用固定大小的摘要来估两篇文档的重合度，找近似重复时不必把文档两两比对。一个 seed 是设计而不是省略：**十六个模型看到的数据完全一样、顺序也一样**，每个尺寸上每一步都是同一个 1024 条序列 × 2048 token 的 batch，所以它们之间的差别只能归到尺寸或者去重上。每个模型有 154 个 checkpoint：初始化时一个，第 1 步到第 512 步之间取对数间隔，之后每 1000 步一个。配套发布了可复现的 dataloader，所以任何一个 checkpoint 都能查出它此前见过哪些 token。作为对照，GPT-2、GPT-3、OPT、T5、BLOOM 发布的 checkpoint 数量在 1 到 30 之间。

154 个 checkpoint 加一个可复现的 dataloader，换来的是能在这次训练本身上验证关于训练的说法。一个例子：直觉上训练后期看到的数据更容易被记住，如果成立，工程上就可以靠排数据顺序来压制记忆。他们用 (32, 32)-memorisation（看每条 context 的前 64 个 token）去量，发现用 Poisson 过程拟合得极好，训练顺序影响很小。剩下能用的建议只有一条：把担心的那些序列放在前面，万一模型真记住了，能在这次训练结束之前就知道。

[DataDecide](https://arxiv.org/abs/2504.11393) 正面处理外推问题。setup：**1050 个模型**、三万多个 checkpoint，25 份预训练语料 × 14 个尺寸（4M 到 1B），每个模型按 100 token/参数训练，是 Chinchilla 的五倍，刻意过训。比较对象不是某个固定 baseline，而是 25 份语料两两互比；指标是十个 OLMES 任务上的 decision accuracy；每个尺寸三个 seed，1B 上是三次完整重跑。总共约 82 万 H100 小时。OLMES 是 Ai2 定的一套评测规程，把 prompt 格式、few-shot 例数和打分方式都固定下来，好让两篇论文说的「MMLU」是同一件事。这 25 份语料覆盖 Dolma、C4、FineWeb、Falcon、DCLM 几条主线，外加它们的质量过滤变体和几种 λ 混合。

*decision accuracy* 问的是一个故意放宽的问题：它不管小模型能不能把大模型的 loss 预测准，只管它有没有把几份语料排对顺序。写成式子，设 `y_A`、`y_B` 是两个配方在 target 尺度上实测的均值，`ŷ_A`、`ŷ_B` 是小尺度上的预测，在所有无序配方对上，decision accuracy 就是满足 `sign(ŷ_A − ŷ_B) = sign(y_A − y_B)` 的那部分所占的比例，取值落在 `[0, 1]`，瞎猜是 0.5。它等于把 Kendall's τ 从 `[−1, 1]` 缩放到 `[0, 1]`。target 尺度上谁赢，由 1B 三个 seed 的平均 accuracy 决定，再在那十个任务上取宏平均。

在单个小尺寸（大约 150M）上给语料排序，1B 上约 80% 的两两比较方向是对的。第二个结论是：**八个 baseline 里没有任何一种 scaling law 方法能越过单尺度 baseline 的 compute–decision accuracy 前沿**。跨几个尺寸拟合一条曲线，大多数团队都在这么做，但相对于「训一个小模型然后直接读排序」并没有换来任何东西。

同一次扫描还有两个结论决定了你该怎么读别人的数字。小尺度上连续的 likelihood 指标胜过 accuracy，而且具体是其中两个。CORRECT PROB 是 `P(正确续写 | 上下文)` 在所有题目上的均值。TOTAL PROB 是 `Σ_c P(c | 上下文)` 的均值，`c` 遍历这道题给出的所有续写选项，对的错的都算进去。两者都按字符数做长度归一化。它们的共同点是都不惩罚落在错误选项上的概率质量，而这正是它们与另外两个的分界：NORM CORRECT PROB 把正确续写的概率除以整个选项集上的和，MARGIN 减掉最好的那个错误续写。后两个跟着离散 accuracy 走，也就继承了它的毛病：小模型接近瞎猜，一个只给「答对」记分的指标拿不出信号。TOTAL PROB 走的是相反方向，还会奖励落在合理错误选项上的概率质量，作者认为这至少说明模型见过这个领域。换成这两个指标以后，code 类 benchmark 的 decision accuracy 从基本没用提到 80%，因为小模型在这个指标下能爬到噪声之上，同时指标仍然跟得住大尺度的 accuracy。在 1B、5× Chinchilla 这一档，某些配方在多数任务上 seed 之间的标准差最高能到 2 个 accuracy 点。这个数字是下面所有数字的尺子：一个用 accuracy 点报出来的收益，得先越过它才值得看；用别的单位报出来的收益，至少要先换算到同一个量级上，才谈得上有没有意义。

[Olmix](https://arxiv.org/abs/2602.12237) 从实践一侧做了一次互补的测量：proxy 能小到什么程度，小到什么程度它给出的排序就和 target 对不上了。

![proxy 能小到什么程度](blogs/images/pdsci-proxy.svg?v=1)

论文 Figure 3 的数字重画。proxy 参数量在 15M 以上时，它给出的排序与同一批配比在 1B 上的排序之间，Spearman 秩相关超过 0.89；到 1M 时降到 0.73。他们最后定在 30M 参数、3B token，ρ = 0.896。那个比较里的 target 是 1B 的 Olmo 2，在 24 个 topic domain 上训 100B token，用 52 个下游任务的 macro-average bits-per-byte 打分。Olmix 最后定在 30M 对 1B 的 target：参数量差约 40 倍，把 token 数算进去，compute 差三个数量级左右。DataDecide 的 150M proxy 只比它的 1B target 小 8 倍。两个数字并不一样，但两边都没在「把 proxy 做大」上找到多少收益，Olmix 自己的相关系数从 15M 的 0.89 到 30M 也只走到 0.896。

## 3. 重复数据的第一种 setup：一小块重复很多遍

重复带来的损害，并不随重复量成比例增加。损害最严重的那段落在一条带上，带宽大约两个数量级，而且模型越大，带子越往重复次数少的一侧移。所以重复得少和重复得极多都相对安全，中间那段才不安全。

这个结果来自 [Hernandez 等人](https://arxiv.org/abs/2205.10487)，也是已发表的最大退化幅度。setup：一批模型，从 1.5M 到 1B，每个恰好训练 100B token（固定 token 预算，属于 Chinchilla 之前的做法），比较对象是完全不含重复数据的运行，指标是留出集上的测试 loss，论文再把它换算成有效模型尺寸的倍数。没有报告重复 seed，也没有报告总共跑了多少次。这 100B 里 90% 不重复抽取，另外 10% 是同一份语料里一个随机小子集的重复，所以重复是在挤掉 unique token。这个被重复的子集可以极小、重复极多次，比如 0.01% 的 token 重复一千遍，也可以大一些、重复少一些。他们扫了 1%、3%、10%、20%、50%、90% 六档重复比例，重复次数跨两个数量级，留出数据里不含任何被重复的内容。

摘要里的说法是：「重复 0.1% 的数据 100 次，可以让 800M 参数模型的性能退化到小一半的模型（400M 参数）的水平，尽管另外 90% 的训练 token 仍然是 unique 的。」正文里同一个数据点写的是「接近一个 340M 参数模型」，所以这篇论文自己前后差了大约 0.35 倍，我按正文取保守值。

作者把这条带的两条边拟合成了关于模型尺寸的幂律 $E = k\,N^{\alpha}$，右边界 `(k, α) = (5.1×10⁷, −0.50)`，左边界 `(4.2×10⁶, −0.56)`。

![重复真正伤人的那片区域](blogs/images/pdsci-degradation.svg?v=2)

这张图按那两条拟合算出。带子向右下方倾斜：模型越大，整片受损区域就越往重复次数少的一侧移。`N = 8×10⁸` 时，两条拟合给出的边界大约是 43 次和 1800 次。虚线是「整份语料过四遍」，也就是第 1 节那个场景，它比这条带子的起点还低一个数量级。两篇论文的分歧就化在这段距离里，开头那个「对不上」其实并不存在。作者给出的机制可以直接从这个几何形状上读出来。把大量数据重复两三遍，模型没有能力把它们记住，所以不会出什么事。把极小的一撮重复一万遍，模型会记住，但这一撮太小，记住它占不了多少容量。中间那片区域里，被重复的数据既记得住，又大到足以吃掉模型相当一部分容量。作者算过模型为什么愿意做这笔交易：800M 模型大约到 2.0 nats/token，400M 大约 2.2，而记住的数据代价为 0，于是 `0.9 × 2.2 + 0.1 × 0 = 1.98 < 2.0`。

把重复比例继续往上推，loss 对重复次数的曲线会走完一整个 double descent，也就是随着重复次数增加，loss 先降、再升到一个更差的区间、然后再降：90% 重复数据时，重复次数从 100 走到 10000，走的就是这条曲线。在那条曲线的峰值处，有效参数的惩罚相当严重，50% 重复时是 10 倍，90% 时是 73 倍。

作者提出过一句外推，并且自己就加了限定：拟合出的边界暗示「在参数量以千亿计的当前最好的语言模型上，数据只重复 2 次就可能带来显著退化」。那是一句有条件的话，条件是他们那种固定 100B token、重复子集随机选取的设定。它不是在说一次现代训练把整份精选语料重复两遍会怎样。

## 4. 重复到底伤到了什么，以及三篇论文如何做到不矛盾

测试 loss 低估了损害。同一批运行里，「复制一段读过的文字」这项能力上损失的有效模型尺寸，是 loss 上看到的三倍；机制上还能定位到具体是哪个电路被取代。

![伤害落在哪里](blogs/images/pdsci-damage.svg?v=1)

论文 Figure 5 和 6 的数字重画。在只有 3% 重复数据、取最坏的重复次数时，在复制被重复过的文字这项能力上，有效模型尺寸损失了 3 倍，而整体测试 loss 最多损失 1.15 倍。prefix matching 损失 1.47 倍。它量的是有多少注意力落在「当前 token 上一次出现时、紧跟其后的那个 token」上，而这正是 induction head 的定义性行为。三个倍数之间差了两倍多，最大的两个都是跨位置复制类的行为。

在一个单层 attention-only 模型里，在 "Potters" 的最后几次出现上，对照模型给 "Pot" 之后的 "ters" 分配了 97% 以上的概率，重复数据模型不到 4%。两层模型上 "Dursley" 这个词，对照给 92%，重复数据模型给 10%，而在构造出来的 "unDursleyish" 上，两者是 68% 对 0.4%。作者的解读是，记住重复数据的压力让一个 skip tri-gram head 完全取代了 induction head。与之一致的是，in-context learning 退化得最厉害：在 double descent 的峰值处，一段重复文字第十一次出现时的 loss 完全不再随着出现次数下降。他们对自己没能证明的部分也交代得很清楚，说 logit attribution 无法区分「induction head 活性变低」和「其他 head 在干扰」。

现在把三个结论并排放。

Hernandez 等人重复的是一个**随机的小子集**，同时**固定总 token 预算**，所以重复挤掉了 unique token，而且重复次数最高测到 10000 次。在这些条件下重复确实会造成破坏，并且在区间中段最糟。

Muennighoff 等人重复的是**整份可用语料**，因为再也没有更多了，约束是 **compute** 而不是 token，epoch 数基本在个位数到两位数之间。在这些条件下前四个 epoch 几乎免费。这里没有矛盾：整份语料跑 4 遍和把 0.1% 的数据重复 100 遍不是同一个实验，对 800M 的模型，拟合出的带子从大约 43 次重复才开始，比 4 高一个数量级。

Pythia 在一份 MinHash 去重过的 Pile 上跑了大约 1.5 个 epoch，什么也没看到，这同样在那条带子的预测之内；它另外报告去重「在语言建模性能上没有明显收益」。最后这句要小心处理：它是定性的，支撑它的图在附录里，而且作者自己就给了一个把结论往回收的解释，即 Pile 本身对精选子集做的上采样，也许和其他论文研究的那种无意重复行为并不是一回事。

Muennighoff 等人从另一个方向得到同样的结论，并且把条件交代清楚了。在 C4 上他们发现 perplexity 过滤有效而去重无效：只保留 perplexity 最低的 25%，4.2B 参数下他们那个重标定过的 19 任务平均分从 22.2 升到 25.3，去重则把它从 22.2 降到 20.5。在更脏的 OSCAR 上两者都有效。他们给出的推广是数据过滤主要对噪声大的数据集有效，这也是 Pythia 那个 null result 最合理的读法，因为 Pile 本来就是精选出来的。

所以这三个结果的适用条件各不相同：整份语料重复几遍，把一小块重复几百遍，以及在一份本来就干净的语料上去重。

## 5. 数据配比：那些定律，以及它们究竟是关于什么的定律

配比这一支要回答三个问题，而它们也正是按这个顺序分开的：loss 是不是配比的可预测函数；优化它能不能换来更好的模型；domain 集合不断变动时这个搜索怎么跑。第一个问题有答案：loss 确实是配比的可预测函数，好几种形式都能把曲面拟合到百分之几以内，最近还有一篇不是拟合出这个形状，而是把它推导了出来。

第一次认真的尝试是 [DoReMi](https://arxiv.org/abs/2305.10429)。setup：撑起头条数字的一共四个模型（280M 的参考模型、280M 的 proxy、8B 的 baseline、8B 的 DoReMi），每个训 200k 步，batch 是 512 × 1024 token，大约 105B token；baseline 是 Pile 的默认 domain 权重，也就是 Pile 论文里按 epoch 上采样之后的比例，不是原始 token 占比；指标是五个生成式任务上的 one-shot exact-match 平均分；论文没有报 seed 数，也没有报方差。

方法是 group distributionally robust optimization：proxy 不去最小化平均 loss，而是最小化最差那个 domain 的 loss，这里的「最差」按相对一个参考模型的超额 loss 来算，而那个参考模型本身就是用默认权重训的；domain 权重就是这个 minimax 里对手收敛到的东西。头条是「相对使用 The Pile 默认 domain 权重的 baseline，把平均下游 accuracy 提高了 6.5 个百分点」，外加用 75k 步就到了 baseline 跑 200k 步的水平。有两件事限制了这 6.5 能读出多少。定义「差距」的那个参考模型，训练用的正是 baseline 权重，所以方法是拿自己被正则化去靠近的那个分布来当对照。以及全篇没有 seed，6.5 个点没有误差棒；作为参照，同一张表里把 proxy 换成 70M、150M、1B 的三次运行，拿到的是 +1.1、+2.5 和 +2.3。22 个 Pile domain 的 perplexity 全部改善，包括那些被调低权重的，而重配的幅度很大：Pile-CC 从 0.1121 到 0.6057，ArXiv 从 0.1052 到 0.0036。把 arXiv 砍到三十分之一，arXiv 自己的 perplexity 反而变好了。一个说得通的解释是，专业 domain 也得先有语言能力，而 web text 是最便宜的语言来源。

[Data Mixing Laws](https://arxiv.org/abs/2403.16952) 提出了那个函数形式，后来的文献一直在争论它。setup：20 种配比，分别在 70M、160M、305M、410M 上各训 30B token，外推到 1B、100B RedPajama token 的 target，比较对象是 RedPajama 的默认配比，指标是 Pile 上的 validation loss（刻意用了和训练不同的语料），没有报告 seed。设一共 `M` 个训练 domain，`r_j` 为 domain `j` 的占比，`L_i` 为验证 domain `i` 上的 loss，

$$
L_i(r_1, \ldots, r_M) \;=\; c_i + k_i \exp\Big(\sum_{j=1}^{M} t_{ij}\, r_j\Big)
$$

每个验证 domain 要拟合 `c_i`、`k_i` 和 `M` 个交互项 `t_ij`，一共 `M + 2` 个数。因为 `k_i > 0`，指数项恒正，所以对任何配比都有 `L_i > c_i`，`c_i` 就是 domain `i` 的 loss 里怎么调配比都动不了的那部分。`t_ij` 为负，表示在 `j` 上训练会降低 `i` 上的 loss。

这个形式的来历是一次两 domain 的小实验。他们在 GitHub 和 Pile-CC 上跑了 70M 和 160M，发现减掉一个常数之后，某个 domain 的 loss 取对数，对它自己的占比是线性的，也就是 $L_i = c_i + k_i \exp(t_{ii} r_i)$。从两个 domain 推到 `M` 个是猜的，只受两条约束：形式必须能退回二 domain 的情形，以及必须对 domain 的重新编号保持对称，因为没有理由偏袒哪一个。满足这两条的候选有四个。落选的那个是每个训练 domain 一个指数再相加，$c_i + \sum_j k_{ij}\exp(t_{ij} r_j)$，拟合精度差不多，但要 `2M + 1` 个系数。指数套在求和外面这一版赢在参数少。

拟合的做法有点特别。这条定律再加上一层可学的验证 domain 加权，整体恰好就是一个单隐层网络，激活函数取指数，输出层过 softmax，所以他们就当成网络来训，外面再套 AdaBoost 做多次拟合来压方差。他们也不直接拟合 Chinchilla 那个双变量曲面，理由是同时放这么多自由参数不稳定，改成先后跑两条：步数上的 $L(S) = E_1 + B/S^{\beta}$，尺寸上的 $L(N) = E_2 + A/N^{\alpha}$，然后才轮到配比定律。

这样复合起来，它为 1B 模型在 100B RedPajama token 上预测的配比，只用 73% 的步数就达到默认配比的 loss。论文另一处把同一件事写成默认配比要多训 48% 的步数才追得上，那个数字是沿着拟合出的步数定律外推的，并没有谁真的训过。[RegMix](https://arxiv.org/abs/2407.01492) 在同一个问题上站到了对面：它干脆不预设任何函数形式。setup：512 个 1M 参数的 proxy，每个训 1B token，配比在 17 个 Pile domain 上从 Dirichlet 采样，迁移到 1B、25B token 的 target，比较对象有五个：Pile 人工权重、纯 Pile-CC、perplexity 过滤、ODM、DoReMi（后两个直接沿用原论文公布的权重再归一化，没有重跑）；指标是 14 个 benchmark 上 0-shot 到 5-shot 的平均分。全文没有出现过「seed」这个词。它拿回归器代替定律，在预测 1B 模型排序这件事上 LightGBM 的 Spearman 是 97.1，线性回归是 88.0，这个差距本身就是曲面非线性的证据。所以这两篇论文分歧的地方，是那个参数化形式到底有没有在干活。

[Scaling Laws for Optimal Data Mixtures](https://arxiv.org/abs/2507.09404) 把这个形式扩展成同时依赖 `N` 和 `D`。只说 LLM 这一组的 setup：7 个 SlimPajama domain 上的 160 次拟合运行，模型 412M 到 1.4B，训练量 4B 到 46B token，比较对象有两个：SlimPajama 的自然比例，以及均匀配比；指标是 CORE 的中位数和 MMLU；每种配比只训一次。验证方式是另训一个 7B 跑 150B token。多模态和视觉那两组我没细看，下面只谈 LLM。他们最好的那个 7B 拿到 CORE 58、MMLU 37，均匀配比是 53 和 30；不过那个配比是照着一份留出的对齐语料的 loss 优化出来的，不是照着预训练 domain 优化的，按他们自己那个「各 domain 平均」目标算出来的配比拿到的是 56 和 32。在他们的加性定律里，交叉导数 $\partial^2 L/\partial N \partial h$ 和 $\partial^2 L/\partial D \partial h$ 为零，所以最优配比与尺度无关，而联合定律让最优点依赖 compute。两者只能有一个对；他们报告的是联合定律拟合得更好。在 LLM 上，他们的验证平均相对误差是 1.21% 到 1.30%，并且从不报 R²，所以跨论文比较拟合质量只能用 MRE。

到这里为止全是拟合出来的曲线。[Dai 和 Zheng](https://arxiv.org/abs/2606.08167) 第一次从机制上解释了这种形状的定律凭什么成立。他们假设一个 domain 内部的 skill 服从幂律，并且不同 domain 共享一段基础 skill 的头部，尾部互不相交。容量有限，各 domain 只能在同一个预算里分，正是这个共享约束把各 domain 的 loss 耦合了起来，产生出那个交互项，也就是所有人一直在经验拟合的东西。但光靠容量竞争会退化：它预测最优训练配比等于目标配比，而没有人观察到这种情况。再加上一项 one-pass SGD 的噪声，这一项只依赖 domain 自己的权重，就打破了对称性，权重会朝更难学的 domain 偏移。

![几种形式各自拟合得如何](blogs/images/pdsci-lawfit.svg?v=1)

论文 Table 2 的数字重画：在 RegMix 公开的那 64 次十亿参数、17 个 Pile domain 的运行上拟合时的平均相对误差。两项式的解释用 5K 个参数，误差 1.533%，加性定律用 K(2K+1) 个参数是 2.209%，RegMix 自己的回归是 6.480%。这张表我不太敢当 benchmark 看：数据是 RegMix 的，拟合是胜出方法的作者自己做的，所以它只能说明方法内部自洽。

## 6. 有没有谁真的赢过了按比例采样

第二个问题的答案是相反的。在目前最仔细的一次对比里，六种已发表的配比方法，DoReMi 也在内，每一种都至少在一组 domain 上输给了等量采样。

[Aioli](https://arxiv.org/abs/2411.05735) 拿六种配比方法去和 stratified sampling 比，后者是不管每组多大都抽同样多的 token。setup 很窄：单一模型尺寸，160M，Pythia 架构，从头训练，SlimPajama 切成六种 domain 设定，分别是两组、三组和七组，小设定训 5000 步、最大的训 40000 步；指标是各组测试 perplexity 的平均；小设定五个 seed，最大的三个。各方法可以额外用最多十次训练来学它的配比；stratified sampling 和 Aioli 是零次。

![没有谁能稳定赢过 baseline](blogs/images/pdsci-aioli.svg?v=1)

论文 Table 2 的数字重画成相对 stratified baseline 的变化量，负值更好。他们的结论是：「就平均测试 perplexity 而言，没有任何现有方法能稳定胜过简单的 stratified sampling baseline」，输得最多的一次是 6.9 个 perplexity。DoReMi 六个设定里输三个，其中一个输了 6.898。DoGE 六个里赢一个。

他们也诊断了原因。他们证明现有方法都是同一个参数形式的实例。把训练切成 `T` 轮，$p^{t} \in \Delta^{m}$ 是第 `t` 轮用的配比，一共 `m` 组，那么

$$
L^{t+1}_{\text{val},i}(p) \;=\; c^t_i + b^t_i\,\sigma\Big(\sum_{j=1}^{m} -A^t_{ij}\, p^t_j\Big)
$$

$A^{t}$ 是这一轮的 `m × m` 交互矩阵，$A^{t}_{ij}$ 表示在第 `j` 组上训练会把第 `i` 组的 loss 推动多少；$b^{t}$ 和 $c^{t}$ 是每组各自的缩放和偏置；`σ` 取恒等函数或者 `exp`。于是一个已发表的方法就是三个选择：`(T, σ)` 这一对、估计 $A^{t}$ 的规则、以及怎么解出 `p`。offline 方法取 `T = 1`、`σ = exp`，扫至少 `m + 1` 个静态配比把 `A` 拟合出来，然后直接解。online 方法取 `T > 1`、`σ = Id`，跑 exponentiated gradient descent，$p^{t+1}_j \propto p^{t}_j \exp\!\big(\eta \sum_i b^{t}_i A^{t}_{ij}\big)$。真正拉开差距的是 $A^{t}$：DoReMi 把它取成对角，$A^{t}_{ii} = \min\{L^{t}_{\mathrm{train},i}(p) - L_{\mathrm{train},i}(f_{\mathrm{ref}}),\, 0\}$，所以只有在模型还落后于参考模型的组上权重才会涨；DoGE 取 $A^{t}_{ij} = \langle \nabla L^{t}_{\mathrm{val},i},\, \nabla L^{t}_{\mathrm{train},j} \rangle$，也就是 `i` 上的验证梯度和 `j` 上的训练梯度的内积。

然后他们把各个零件分开检验。参数化足够准：把这些定律拟合到 simplex 上的扫描数据，静态 log-linear 形式 R² 为 0.991，线性动态形式为 0.947。求解器足够准：贪心下降在三个设定里的两个上恢复了最优的动态占比。按各方法估出的 `A` 与真值近似之间的相似度给它们打分，相似度与「相对 stratified 的改进」之间的相关是 R² = 0.491。三个零件里前两个都站得住，出问题的是对 $A^{t}$ 的估计。

Aioli 自己的做法顺着这个诊断而来。直接把 $A^{t}$ 读出来要额外训 `m` 次，一个 one-hot 配比一次，所以它改成从每一轮里切出 $\delta$ 这一小段，再把这一段分成 `K = mk` 个区间。这些区间上用的是平滑过的 one-hot 配比，$p^{t,i} = (1-\varepsilon)\mathbf{1}_i + \varepsilon\,\mathrm{Unif}(m)$，顺序是每种各 `k` 份随机打乱后交错排列，好让模型在每个 one-hot 配比上花的时间摊在整个 $\delta$ 里，而不是挤在末尾一整块。记下每个区间之后各组验证 loss 掉了多少，得到矩阵 `β`，它满足 $\beta_i = P A^{t}_i$，`P` 是那 `m` 个配比堆起来的矩阵，于是每组解一次线性方程组就能还原出 $A^{t}$。额外训练次数为零。它在六个设定上全部胜过 stratified，平均 0.274 个 perplexity。这是个不大的数字。perplexity 和 DataDecide 那把 accuracy 点的尺子不是同一个单位，没法直接比，但可以定个位：这张表里最好和最差的方法之间也不到 7 个 perplexity，而论文自己主张的是稳定而不是幅度，六个设定里 Aioli 只在两个上是最好的方法。在一个更现实的设定里，每个方法只有 0.5 次额外运行而不是十次，用某方法的配比做初始化再交给 Aioli 继续，30 个「方法 × 设定」组合里改善了 28 个，平均 1.202 个 perplexity。

160M 模型加 SlimPajama 是一个很窄的测试条件，作者自己也说，在七组的设定下十次运行的预算可能让 offline 方法吃了亏。即便如此，这仍是目前最直接的一次对比，而它给出的收益比这一支文献通常暗示的小。

## 7. 实践收敛到了什么

第三个问题是，domain 集合会一直变，这个搜索在流水线上该怎么跑。真建过一条这样的流水线之后给出的答案是：大部分代价可以省掉。domain 变动之后复用此前的 proxy 运行，能拿回从头重算所带来收益的绝大部分，而 compute 只要四分之一。

[Olmix](https://arxiv.org/abs/2602.12237) 是真正用来预训练 Olmo 3 的那套框架，它把配比搜索当成工程问题来做，并把设计空间逐项量了一遍。setup：proxy 是 30M 参数、3B token，target 是 1B 的 Olmo 2 训 100B token，起步是 24 个 DCLM topic domain，比较对象是自然分布（权重正比于 domain 大小），指标是 52 个下游任务上 bits-per-byte 的宏平均，在 proxy swarm 的采样上跑了三个 seed，其中两张图报了 min-max 区间。bits-per-byte 是把交叉熵按原始 UTF-8 字节数归一化，而不是按 token 数，这样不同 tokenizer 的模型之间才可比，perplexity 做不到这一点。swarm 指的是拟合回归所用的那一批 proxy 运行，一个候选配比一次。他们逐项量了七个设计选择。

其中两个答案推翻了早前工作里默认的假设。样本复杂度，也就是 swarm 需要多少次 proxy 运行，对 domain 数量是线性的：6、12、18、24 个 domain 的误差曲线，在按 `K = c(m+1)` 中的 `c` 作横轴时会重合，他们建议 `K ≥ 3(m+1)`。此前几篇 mixing law 的论文假设的是平方，并据此确定了自己的 swarm 规模。回归族怎么选，其实和 swarm 规模纠缠在一起：25 次运行时 BiMix 赢，LightGBM 要 118 次以上，swarm 一旦足够大，log-linear 回归整体最好，ρ = 0.80。所以在一个固定的小 swarm 上比较回归族，比出来的是它们在那个样本量下的表现。

domain 集合本身在不断变化，学术文献完全没有建模这一点。他们模拟了一段五次更新的开发序列，从 24 个 domain 走到 64 个：加入十五种 Stack-Edu 语言、再加六个来源、修订一个、移除一个、把一个拆成二十个。

![跨 domain 更新复用 swarm](blogs/images/pdsci-olmix.svg?v=1)

论文 Figure 10 的数字重画。每次更新都从头重算配比，代价是 832 次 proxy 运行，相对自然分布拿到 12.2% 的 bits-per-byte 改进。这段模拟最后停在 64 个 domain，不是前面配置研究里那 24 个。把未受影响的 domain 之间的比例固定住、只在降维后的空间里求解，得到 11.6%，是前者的 95%，只需 216 次运行，省下 74%。部分复用的变体用 272 次运行拿到 12.0%。

这个 12% 我第一遍读成了「Olmix 比 DoReMi 那些方法好 12%」，其实不是。论文里唯一的端到端 baseline 是自然分布，也就是权重正比于 domain 大小；DoReMi、RegMix、均匀配比都没有被当成完整方法拿来正面比过。对一个工程决策来说，自然分布是对的 baseline，但它不能用来回答哪种方法更好。

## 8. 效应有多大

这套做法便宜，而且管用。30M 的 proxy 在 1B target 上给配比排序能到 ρ ≈ 0.9；150M 的 proxy 能对上 80% 的语料两两比较；而跨尺寸拟合 scaling law，在同等 compute 下这两件事都赢不过。这套做法量出来的结果都一样：效应相对噪声很小。DataDecide 测到 1B 处 seed 之间的标准差可达两个 accuracy 点，而它也是这篇里唯一量过 seed 方差的一篇：DoReMi、Data Mixing Laws、RegMix、最优配比那篇都没报，它们的头条差距全是一次运行对一次运行。已发表的数据处理收益里，有相当一部分就是这段没人量过的散布的大小。

真正在起作用的是那些条件。整份语料重复几遍接近免费，把其中一块重复一百遍是灾难。去重有没有用，取决于语料本来有多脏。至于最优配比与尺度是否有关，同一篇论文里的两条定律给的答案就不一样。要化解这里面任何一处分歧，都得回去读 setup：固定住的是什么，compute 还是 token；baseline 是什么，一个调过的替代方案还是干脆什么都不做；用了几个 seed，它们之间的散布有多大；结论是在什么尺度上测的，而你要用它的尺度又是多少。
