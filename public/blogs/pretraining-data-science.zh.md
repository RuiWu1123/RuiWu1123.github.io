把预训练语料里 0.1% 的部分重复一百遍，800M 的模型最后表现得像 400M。把整份语料重复四遍，loss 只高 0.5%。在去重过的 Pile 上训 1.5 个 epoch，去重这件事什么也没测出来。

三个都是真结果，分别来自 Hernandez 等人、Muennighoff 等人和 Pythia。它们对不上，是因为重复的东西不一样，预算也不一样，每个数字的适用范围就是产生它的那次运行。

所以下面每个结论都连着 setup 一起写：多少个模型、多大、训了多少 token、跟什么 baseline 比、用什么指标测。

## 1. 坐标系，以及数据受限时要做的修正

[Chinchilla](https://arxiv.org/abs/2203.15556) 把 loss 曲面拟合成 `L(N, D) = E + A/N^α + B/D^β`，用 400 多个模型拟合，参数量 70M 到 16B，训练量 5B 到 500B token，得到 `E = 1.69`、`A = 406.4`、`B = 410.7`、`α = 0.34`、`β = 0.28`。后面一切说法都建立在它那个结论上：固定 compute 预算下，参数量和 token 数应当等比例放大。

藏在里面的假设是：最优点要多少 token 就能买到多少，且质量不变。[Muennighoff 等人](https://arxiv.org/abs/2305.16264) 把这个假设去掉，重新推了一遍曲面。这篇论文被引用的次数远多于被读完的次数，所以 setup 原样写一遍：400 多个模型，10M 到 9B 参数，总计最多 900B token，最多 1500 个 epoch，全部在 C4 的子集上，GPT-2 架构和 tokenizer，cosine schedule 在训练过程中衰减 10 倍，并且刻意不做 early stopping，好让 overfitting 显出来，而不是被绕开。这些子集是嵌套的，所以 unique data 更少的那一组看到的一定是更大那一组的子集。loss 在留出的测试集上算，这一点和 Chinchilla 不同，后者报的是训练 loss。

他们的模型引入了两个量。设 unique token 数为 `U_D`，重复次数 `R_D = D/U_D − 1`，那么*有效*数据量，也就是「换成全新数据、能达到同样 loss 所需要的量」，写成

$$
D' \;=\; U_D + U_D\, R_D^{*}\left(1 - e^{-R_D / R_D^{*}}\right)
$$

多余参数 `R_N` 对应的有效参数 `N'` 写法与此对称。用 182 次运行拟合得到 `R_D* = 15.39`、`R_N* = 5.31`，作者把它们叫作重复数据和多余参数各自的半衰期。

![多跑一个 epoch 值多少](blogs/images/pdsci-repetition.svg?v=1)

这张图是这里按上面那个表达式算的。四个 epoch 相当于 3.73 份语料，广为流传的「四个 epoch 之内基本免费」就是从这里来的；论文自己举了个例子：8.7B 模型在 44B unique token 上跑完四个 epoch，validation loss 只比同样模型在 178B unique token 上高 0.5%。十六个 epoch 相当于 10.58 份。这条曲线的上限是 `1 + R_D* = 16.4`：无论怎么重复，一份语料的价值都到不了自身的 16.4 倍以上。图里的边际那一列是推出来的，不是抄的，因为那个指数形式意味着第 k 个 epoch 相对于一个新 token 的价值是 `e^{−(k−1)/15.39}`；论文给了上限和半衰期，但没有逐 epoch 列过表。

后面还有两个推论，很少有人转述。因为 `R_N* < R_D*`，多余参数掉价比重复数据更快，所以在数据受限的时候，多出来的 compute 应该先花在 epoch 上而不是参数上，这和 Chinchilla 的等比例建议正好相反。他们在大尺度上验证过：在 9.3×10²¹ FLOPs、25B unique token 的条件下，模型参数量比 Chinchilla 规定的少 27%，loss 反而更好。

这个上限本身还能抬高，办法是改变「什么算语料」。他们从 The Stack 里混入 Python，发现即使只在自然语言上评测，code 占比到 50% 都不掉点，因此 code 相当于把有效 token 数翻了一倍。合起来的建议写得很直接：先用 code 把数据量翻倍，再重复四遍，得到「8 倍的训练 token，效果预期等同于真有 8 倍的 unique data」。他们十九项评测里有两项只要加了一点 code 就立刻变好：bAbI 在 10% code 时从 0.0 到 12.5，WebNLG 从 4.8 到 9.5，作者认为是 code 让模型学会了长程的状态追踪。

## 2. 一个数据实验凭什么可信

这篇后面所有的结论，都建立在「从小实验推到大实验」这一步上。这一步本身也是研究对象。

[Pythia](https://arxiv.org/abs/2304.01373) 就是为了让这一步能被人审计才做的。十六个模型，八个尺寸从 70M 到 12B，两个数据版本（Pile 和去重后的 Pile），每个模型训练的 token 数都精确等于 299,892,736,000，还有很少见的一点：**所有模型看到的数据完全一样、顺序也一样**，每个尺寸上每一步都是同一个 1024 条序列 × 2048 token 的 batch。每个模型有 154 个 checkpoint：初始化时一个，第 1 步到第 512 步之间取对数间隔，之后每 1000 步一个。配套发布了可复现的 dataloader，所以任何一个 checkpoint 都能对应到此前见过的究竟是哪些 token。作为对照，GPT-2、GPT-3、OPT、T5、BLOOM 发布的 checkpoint 数量在 1 到 30 之间。这套东西是一台仪器。

仪器立刻给出了一个否定结果，推翻的是一个流传很广的机制。直觉上训练后期看到的数据更容易被记住，如果成立，工程上就可以靠排数据顺序来压制记忆。他们用 (32, 32)-memorisation（看每条 context 的前 64 个 token）去测，发现「Poisson 模型拟合得极好」，也就是说训练顺序影响很小：被记住的序列并不在开头或结尾更密集。他们从中给出的实践建议是：你没法靠重排数据减少记忆，但可以把担心的那些序列放在前面，这样万一模型真记住了，你能在这次训练结束之前就知道。

[DataDecide](https://arxiv.org/abs/2504.11393) 正面处理外推问题，用的是这个方向上最大的一次受控扫描：25 份预训练语料 × 14 个尺寸（4M 到 1B）× 3 个 seed，一共 **1050 个模型**、三万多个 checkpoint，约 82 万 H100 小时。每个模型都按 100 token/参数训练，是 Chinchilla 的五倍，刻意过训。那 25 份语料不是玩具：Dolma 1.7 加四种 domain ablation、C4、FineWeb-Pro、FineWeb-Edu、Falcon、五种 Falcon+CC 质量过滤变体、六种 DCLM-Baseline 变体，以及三种 DCLM 与 Dolma 的 λ 混合。用 *decision accuracy* 衡量：小尺度上语料两两之间的排序，有多大比例和 1B 上的一致。

他们最主要的结论是：在单个小尺寸（大约 150M）上给语料排序，能对上 1B 目标处约 80% 的两两比较。第二个结论是：**八个 baseline 里没有任何一种 scaling law 方法能越过单尺度 baseline 的 compute–decision accuracy 前沿。**跨几个尺寸拟合一条曲线，大多数团队都在这么做，但相对于「训一个小模型然后直接读排序」并没有换来任何东西。

同一次扫描还有两个结论决定了你该怎么读别人的数字。小尺度上连续的 likelihood 指标胜过 accuracy，而且具体是正确答案的*原始* likelihood；归一化版本会惩罚错误选项上的概率质量，表现更差。换成原始 likelihood 以后，code 类 benchmark 的可预测性「从没法用变成 80%」，因为小模型在这个指标下能爬到噪声之上，同时指标仍然跟得住大尺度的 accuracy。噪声本身并不小：在 1B、5× Chinchilla 这一档，某些配方在多数任务上 seed 之间的标准差「可以高达 2 个百分点的 accuracy」。任何低于两个点的数据处理收益，都在单次训练的噪声之内。

[Olmix](https://arxiv.org/abs/2602.12237) 从实践一侧做了一次互补的测量：proxy 能小到什么程度，小到什么程度它给出的排序就和 target 对不上了。

![proxy 能小到什么程度](blogs/images/pdsci-proxy.svg?v=1)

论文 Figure 3 的数字重画。proxy 参数量在 15M 以上时，它给出的排序与同一批配比在 1B 上的排序之间，Spearman 秩相关超过 0.89；到 1M 时降到 0.73。他们最后定在 30M 参数、3B token，ρ = 0.896。那个比较里的 target 是 1B 的 Olmo 2，在 24 个 topic domain 上训 100B token，用 52 个下游任务的 macro-average bits-per-byte 打分。两个独立的团队，用不同的语料和不同的 target，落到了同一个位置：proxy 可以比 target 小四个数量级，把 proxy 做大换不来什么。

## 3. 重复数据的第一种 setup：一小块重复很多遍

那些吓人的数字来自 [Hernandez 等人](https://arxiv.org/abs/2205.10487)，他们的 setup 非常具体。每个模型都恰好训练 100B token，这是一个固定的预算，属于 Chinchilla 之前的做法。这 100B 里 90% 是不重复抽取的，另外 10% 是同一份语料里一个随机小子集的重复，所以重复是在*挤掉* unique token，而不是额外加上去。这个被重复的子集可以极小、重复极多次，比如 0.01% 的 token 重复一千遍，也可以大一些、重复少一些。他们扫了 1%、3%、10%、20%、50%、90% 六档重复比例，模型从 1.5M 到 1B，重复次数跨两个数量级。测试 loss 在留出数据上算，留出数据里不含任何被重复的内容。

摘要里的说法是：「重复 0.1% 的数据 100 次，可以让 800M 参数模型的性能退化到小一半的模型（400M 参数）的水平，尽管另外 90% 的训练 token 仍然是 unique 的。」正文里同一个数据点写的是「接近一个 340M 参数模型」，所以这篇论文自己前后差了大约 0.35 倍，保守的读法是取正文。

退化程度对重复量并不单调。最严重的区间是一条带，作者把这条带的两条边拟合成了关于模型尺寸的幂律 `E = k·N^α`，右边界 `(k, α) = (5.1×10⁷, −0.50)`，左边界 `(4.2×10⁶, −0.56)`。

![重复真正伤人的那片区域](blogs/images/pdsci-degradation.svg?v=1)

这里按那两条拟合算出来的。带子向右下方倾斜：模型越大，造成最大伤害所需要的重复次数越少。作者给出的机制可以直接从这个几何形状上读出来。把大量数据重复两三遍，模型没有能力把它们记住，所以不会出什么事。把极小的一撮重复一万遍，模型会记住，但这一撮太小，记住它占不了多少容量。中间那片区域里，被重复的数据*既*记得住，*又*大到足以吃掉模型相当一部分容量。作者算过模型为什么愿意做这笔交易：800M 模型大约到 2.0 nats/token，400M 大约 2.2，而记住的数据代价为 0，于是 `0.9 × 2.2 + 0.1 × 0 = 1.98 < 2.0`。就局部而言，记住更划算。

把重复比例继续往上推，这个凹陷会变成 double descent：90% 重复数据、重复 100 到 10000 次时，loss 先降、再升、再降。在那条曲线的峰值处，有效参数的惩罚相当严重，50% 重复时是 10 倍，90% 时是 73 倍。

有一句外推，作者提出时自己就加了限定，却最常被人脱离语境引用：拟合出的边界暗示「在参数量以千亿计的当前最好的语言模型上，数据只重复 2 次就可能带来显著退化」。那是一句有条件的话，条件是他们那种固定 100B token、重复子集随机选取的设定。它不是在说一次现代训练把整份精选语料重复两遍会怎样，第 4 节讲的就是这个区别为什么重要。

## 4. 重复到底伤到了什么，以及三篇论文如何做到不矛盾

loss 的数字低估了伤害。

![伤害是集中的，不是摊平的](blogs/images/pdsci-damage.svg?v=1)

论文 Figure 5 和 6 的数字重画。在只有 3% 重复数据、取最坏的重复次数时，复制一段被重复过的文字这项能力损失了 3 倍的有效模型尺寸，而整体测试 loss 最多损失 1.15 倍。prefix matching，也就是探测 induction head 的那个标准行为指标，损失 1.47 倍。伤害集中落在与泛化相关的那些机制上。

机制层面的证据对一篇 scaling 论文来说，具体得少见。在一个单层 attention-only 模型里，在 "Potters" 的最后几次出现上，对照模型给 "Pot" 之后的 "ters" 分配了 97% 以上的概率，重复数据模型不到 4%。两层模型上 "Dursley" 这个词，对照给 92%，重复数据模型给 10%，而在构造出来的 "unDursleyish" 上，两者是 68% 对 0.4%。作者的解读是「记住重复数据的压力导致 skip tri-gram head 完全取代了 induction head」。与之一致的是，in-context learning 退化得最厉害：在 double descent 的峰值处，一段重复文字第十一次出现时的 loss 完全不再随着出现次数下降。他们对自己没能证明的部分也交代得很清楚，说 logit attribution 无法区分「induction head 活性变低」和「其他 head 在干扰」。

现在把三个结论并排放。

Anthropic 重复的是一个**随机的小子集**，同时**固定总 token 预算**，所以重复挤掉了 unique token，而且重复次数最高测到 10000 次。在这些条件下重复确实会造成破坏，并且在区间中段最糟。

Muennighoff 等人重复的是**整份可用语料**，因为再也没有更多了，约束是 **compute** 而不是 token，epoch 数基本在个位数到两位数之间。在这些条件下前四个 epoch 几乎免费。这里没有矛盾：整份语料跑 4 遍和把 0.1% 的数据重复 100 遍不是同一个实验，Anthropic 那条带子把 800M 模型的伤害峰值放在大约 100 次重复处，比 4 大了一个多数量级。

Pythia 在一份 MinHash 去重过的 Pile 上跑了大约 1.5 个 epoch，什么也没看到，这同样在那条带子的预测之内；它另外报告去重「在语言建模性能上没有明显收益」。最后这句要小心处理：它是定性的，支撑它的图在附录里，而且作者自己就给了一个把结论往回收的解释，即 Pile 本身对精选子集做的上采样也许和其他论文研究的那种无意重复行为不同，或者说「去重数据通常胜过未去重数据这一倾向，主要是在陈述其他工作所用数据的质量」。

Muennighoff 等人从另一个方向得到同样的结论，并且把条件交代清楚了。在 C4 上他们发现 perplexity 过滤有效而去重无效：只保留 perplexity 最低的 25%，4.2B 参数下他们那个重标定过的 19 任务平均分从 22.2 升到 25.3，去重则把它从 22.2 降到 20.5。在更脏的 OSCAR 上两者都有效。他们给出的推广是「数据过滤主要对噪声大的数据集有效」，这也是 Pythia 那个 null result 最合理的读法，因为 Pile 本来就是精选出来的。

所以总结是有条件的：整份语料重复几遍接近免费；把其中一小块重复几百遍不是；而去重的收益，与你动手之前语料有多脏成正比。

## 5. 数据配比：那些定律，以及它们究竟是关于什么的定律

配比是数据工作里唯一长得像干净优化问题的一块，也因此积累了最多的形式化。这些形式化可以拆成三个命题，它们应当分开检验：loss 是配比的可预测函数；这个函数可以被便宜地拟合；优化拟合出来的函数能得到更好的模型。

第一次认真的尝试是 [DoReMi](https://arxiv.org/abs/2305.10429)，它训练一个 280M 的 proxy，在 domain 上做 group distributionally robust optimization，模型去最小化相对参考模型的最坏 excess loss，domain 权重由内层的最大化给出，然后把这些权重迁移到大 30 倍的模型上。它报告「相对使用 The Pile 默认 domain 权重的 baseline，把平均 few-shot 下游 accuracy 提高了 6.5 个百分点」，并且用 75k 步达到 baseline 200k 步的 accuracy。22 个 Pile domain 的 perplexity 全部改善，*包括那些被调低权重的*，而且重配的幅度很大，Pile-CC 从 0.1121 到 0.6057，ArXiv 从 0.1052 到 0.0036。把 arXiv 砍到三十分之一，arXiv 的 perplexity 反而变好了。一个专业 domain 最需要的，是模型先学会语言，web text 就是最便宜的那条路。

[Data Mixing Laws](https://arxiv.org/abs/2403.16952) 提出了那个函数形式，后来的文献一直在争论它。设 `r_j` 为训练 domain `j` 的占比，`L_i` 为验证 domain `i` 上的 loss，

$$
L_i(r_1, \ldots, r_M) \;=\; c_i + k_i \exp\Big(\sum_{j=1}^{M} t_{ij}\, r_j\Big)
$$

其中 `t_ij` 为负表示 `j` 对 `i` 有帮助。指数在求和之外，这让参数量对 domain 数量保持线性而不是平方。与另外两条关于训练步数和模型尺寸的定律复合之后，它为 1B 模型预测了一个配比，在 100B RedPajama token 上，效果相当于默认配比多训 48% 的步数。[RegMix](https://arxiv.org/abs/2407.01492) 干脆不要函数形式，训练 512 个 1M 参数的模型，每个 1B token，配比从 Dirichlet 采样，然后拟合一个回归器；在预测 1B 模型排序这件事上 LightGBM 的 Spearman 是 97.1，线性回归是 88.0，这个差距本身就是曲面非线性的证据。

[Scaling Laws for Optimal Data Mixtures](https://arxiv.org/abs/2507.09404) 把这个形式扩展成同时依赖 `N` 和 `D`，并在三种模态上验证。LLM 那一组用了 7 个 SlimPajama domain 上的 160 种配比，模型 412M 到 1.4B，在 3B 和 7B 上验证；多模态和视觉两组分别是 127 和 95 种配比。在他们的*加性*定律里交叉导数 `∂²L/∂N∂h` 和 `∂²L/∂D∂h` 为零，所以最优配比与尺度无关，而他们的*联合*定律让最优点依赖 compute。两者只能有一个对；他们报告的是联合定律拟合得更好。在 LLM 上，他们的验证平均相对误差是 1.21% 到 1.30%，并且从不报 R²，所以跨论文比较拟合质量只能用 MRE。

[Dai 和 Zheng](https://arxiv.org/abs/2606.08167) 第一次从机制上解释了这样一条定律凭什么成立。他们假设一个 domain 内部的 skill 服从幂律，并且不同 domain 共享一段基础 skill 的头部，尾部互不相交。有限的容量于是强制在共享预算下对各 domain 做分配，正是这个共享约束把各 domain 的 loss 耦合了起来，产生出那个交互项，也就是所有人一直在经验拟合的东西。但光靠容量竞争会退化：它预测最优训练配比等于目标配比，而没有人观察到这种情况。再加上一项 one-pass SGD 的噪声，这一项只依赖 domain 自己的权重，就打破了对称性，权重会朝更难学的 domain 偏移。

![几种形式各自拟合得如何](blogs/images/pdsci-lawfit.svg?v=1)

论文 Table 2 的数字重画：在 RegMix 公开的那 64 次十亿参数、17 个 Pile domain 的运行上拟合时的平均相对误差。两项式的解释用 5K 个参数，误差 1.533%，加性定律用 K(2K+1) 个参数是 2.209%，RegMix 自己的回归是 6.480%。这个比较是在 RegMix 的数据上、由胜出方法的作者做的，所以它只说明内部自洽。

## 6. 有没有谁真的赢过了按比例采样

定律拟合得上，拟合也便宜。优化它们能不能得到更好的模型是另一个问题，最仔细的那个回答是否定的。

[Aioli](https://arxiv.org/abs/2411.05735) 拿六种配比方法去和 stratified sampling 比，后者只是对每组等量采样。setup 很窄：单一模型尺寸，160M，Pythia 架构，从头训练，SlimPajama 切成六种 domain 设定，分别是两组、三组和七组，小设定训 5000 步、最大的训 40000 步，小设定五个 seed、最大的三个，指标是各组测试 perplexity 的平均。各方法可以额外用最多十次训练来学它的配比；stratified sampling 和 Aioli 是零次。

![没有谁能稳定赢过 baseline](blogs/images/pdsci-aioli.svg?v=1)

论文 Table 2 的数字重画成相对 stratified baseline 的变化量，负值更好。他们的结论是：「就平均测试 perplexity 而言，没有任何现有方法能稳定胜过简单的 stratified sampling baseline」，并且每种方法至少在一种设定上输，最多输 6.9 个 perplexity。DoReMi 作为其中被引用最多的方法，六个设定里输三个，其中一个输了 6.898。DoGE 六个里赢一个。

他们也诊断了原因。他们证明现有方法都是同一个参数形式的实例，其中下一步的 loss 是 `L^{t+1}(p) = σ(A^t p^t)`，`A_ij` 编码在第 `j` 组上训练如何影响第 `i` 组的 loss；offline 方法用的是静态的 log-linear 版本，online 方法用的是线性的动态版本，由 exponentiated gradient descent 求解。然后他们把各个零件分开检验。参数化足够准：把这些定律拟合到 simplex 上的扫描数据，静态 log-linear 形式 R² 为 0.991，线性动态形式为 0.947。求解器足够准：贪心下降在三个设定里的两个上恢复了最优的动态占比。错的是*参数*。按各方法估出的 `A` 与真值近似之间的相似度给它们打分，相似度与「相对 stratified 的改进」之间的相关是 R² = 0.491。这些方法是在用对的工具解对的问题，只是数字错了。

Aioli 自己的做法顺着这个诊断而来：从训练自身的 loss 轨迹里估计 `A`，办法是每一轮花一小部分步数跑 one-hot 配比，读出各组的 loss 变化量，额外训练次数为零。它在六个设定上全部胜过 stratified，平均 0.274 个 perplexity。0.274 很小，论文主张的是稳定性：六个设定里，Aioli 只在两个上是最好的方法。在一个更现实的设定里，每个方法只有 0.5 次额外运行而不是十次，用某方法的配比做初始化再交给 Aioli 继续，30 个「方法 × 设定」组合里改善了 28 个，平均 1.202 个 perplexity。

160M 模型加 SlimPajama 是一个很窄的测试条件，作者自己也说，在七组的设定下十次运行的预算可能让 offline 方法吃了亏。这个结果仍然是迄今最直接的一次对比：截至 2025 年，配比优化买到的东西比相关文献所暗示的要少。

## 7. 实践收敛到了什么

[Olmix](https://arxiv.org/abs/2602.12237) 是真正用来预训练 Olmo 3 的那套框架，它把配比搜索当成工程问题来做，设计空间是量过的。他们固定的 target 是 1B 的 Olmo 2，24 个 DCLM topic domain 上训 100B token，在 52 个任务上评测，然后扫了七个设计问题。

其中两个答案推翻了早前工作里默认的假设。关于 domain 数量的样本复杂度是**线性的，不是平方的**：6、12、18、24 个 domain 的误差曲线，在按 `K = c(m+1)` 中的 `c` 作横轴时会重合，他们建议 `K ≥ 3(m+1)`。此前几篇 mixing law 的论文假设的是平方，并据此确定了自己的 swarm 规模。回归族怎么选，这个问题其实被 swarm 规模搅在了一起：25 次运行时 BiMix 赢，LightGBM 要 118 次以上，swarm 一旦足够大，log-linear 回归整体最好，ρ = 0.80。在一个固定的小 swarm 上比较回归器，测到的其实不是你以为在测的东西。

domain 集合本身在不断变化，学术文献完全没有建模这一点。他们模拟了一段五次更新的开发序列，从 24 个 domain 走到 64 个：加入十五种 Stack-Edu 语言、再加六个来源、修订一个、移除一个、把一个拆成二十个。

![跨 domain 更新复用 swarm](blogs/images/pdsci-olmix.svg?v=1)

论文 Figure 10 的数字重画。每次更新都从头重算配比，代价是 832 次 proxy 运行，相对自然分布拿到 12.2% 的 bits-per-byte 改进。把未受影响的 domain 之间的比例固定住、只在降维后的空间里求解，得到 11.6%，是前者的 95%，只需 216 次运行，省下 74%。部分复用的变体用 272 次运行拿到 12.0%。

这些数字要配一条限定：唯一的端到端 baseline 是自然分布，也就是权重正比于 domain 大小。这里没有把 DoReMi、RegMix 或均匀配比当成完整方法来做正面比较。所谓「好 12%」是相对于完全不做配比优化，这对工程决策是对的 baseline，对「哪种方法赢」的论断则不是。

## 8. 效应有多大

那套装置便宜，而且管用。30M 的 proxy 在 1B target 上给配比排序能到 ρ ≈ 0.9；150M 的 proxy 能对上 80% 的语料两两比较；跨尺寸拟合 scaling law 两者都赢不过。这套装置反复发现，效应相对噪声都很小。DataDecide 测到 1B 处 seed 之间的标准差可达两个 accuracy 点，Aioli 测到目前最好的配比方法只比按比例采样好 0.27 个 perplexity。已发表的数据处理收益里有相当一部分就落在这个区间内。

真正在起作用的是那些条件。重复是接近免费还是灾难性的，取决于你是把整份语料重复几遍，还是把其中一块重复一百遍。去重是有用还是没用，取决于语料本来有多脏。最优配比与尺度无关还是有关，取决于你拟合的是同一篇论文里两条定律中的哪一条。要化解这里面任何一处分歧，都得回去读 setup：固定住的是什么，compute 还是 token；baseline 是什么，一个调过的替代方案还是干脆什么都不做；用了几个 seed，它们之间的散布有多大；结论是在什么尺度上测的，而你要用它的尺度又是多少。
